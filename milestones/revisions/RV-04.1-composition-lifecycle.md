## 1. Why this revision exists

`ITfComposition::Release()` only decrements a reference. It does **not** end a composition. Ending requires either:

- the owner calling `ITfComposition::EndComposition(ec)` inside an edit session, or
- the context owner calling `ITfContextOwnerCompositionServices::TerminateComposition(...)`, which invokes `ITfCompositionSink::OnCompositionTerminated`.

The adapter currently releases in four places without ending:

| Site | Code | Consequence |
|---|---|---|
| Destructor | [`borno_tsf.cpp:207-211`](../../native/borno-tsf/borno_tsf.cpp#L207-L211) | composition left live |
| `Deactivate` | [`borno_tsf.cpp:331-336`](../../native/borno-tsf/borno_tsf.cpp#L331-L336) | stuck composing range |
| Focus change | [`borno_tsf.cpp:415-431`](../../native/borno-tsf/borno_tsf.cpp#L415-L431) | stuck range across documents |
| Commit/cancel | [`borno_tsf.cpp:718-721`](../../native/borno-tsf/borno_tsf.cpp#L718-L721), `:745-748` | `Release()` after `EndComposition()` with no re-entrancy guard |

**Crash path:** if focus loss leaves a live composition whose sink is the TIP object, and the TIP is later destroyed, the framework can call `OnCompositionTerminated` on freed memory. Because this DLL is in-process, that is a use-after-free inside Word, Explorer, or a browser.

A second path: if `EndComposition` synchronously invokes the sink (framework-dependent), the sink nulls `m_pComposition`, and the next line dereferences it.

---

## 2. Required invariants

Encode these as comments in the class and as `assert`s in debug builds:

- **I1 — Single owner of the end.** Every composition that is started is ended exactly once by the TIP, or is known to have been terminated by the framework (sink called).
- **I2 — Null before end.** `m_pComposition` is set to `nullptr` *before* calling any function that can re-enter (`EndComposition`, `TerminateComposition`), and the local pointer is used afterwards.
- **I3 — Sink identity.** `OnCompositionTerminated` only affects state if `pComposition ==` the stored pointer; otherwise it is a stale notification and must be ignored.
- **I4 — No engine mutation outside an edit session** (already true; keep it).
- **I5 — No composition survives `Deactivate`.** Either it is ended, or it is terminated through the context owner before the TIP can be destroyed.
- **I6 — No callback into a dead object.** A `m_isTerminating` flag prevents the sink from touching engine state while the service is shutting down.

## 4. Design

### 4.1 Track the active context

Add:

```cpp
ITfContext* m_pActiveContext = nullptr; // AddRef'd
```

- Set in `OnSetFocus`/activation for the focused document; `Release()` the previous one.
- Clear (with `Release`) in `Deactivate` after the composition has been ended.

### 4.2 A single end helper

```cpp
// Ends the active composition, if any, on the given context.
// Precondition: caller holds a read/write edit cookie for `pic`.
HRESULT EndActiveComposition(ITfContext* pic, TfEditCookie ec);
```

Implementation order:

1. `ITfComposition* comp = m_pComposition; m_pComposition = nullptr;`
2. If `comp` is null → return `S_OK`.
3. `ClearDisplayAttribute(ec, pic, range)` (if the range is still valid).
4. `comp->EndComposition(ec);`
5. `comp->Release();`
6. `m_isComposing = false;` and hide the candidate window.

### 4.3 Ending on focus loss / deactivate

Focus loss and deactivate do not always provide a usable edit cookie. Use this order:

1. If a synchronous edit session is available, request one that calls the end helper.
2. Otherwise obtain `ITfContextOwnerCompositionServices` from the context and call `TerminateComposition(comp)`. This is the framework-sanctioned path and will invoke the sink.
3. If both fail, log a non-content diagnostic and **do not** release the pointer blindly; leave it for the sink and mark the TIP as terminating.

Never call `EndComposition` from inside `OnCompositionTerminated` (the sink receives only `ecWrite` and the composition is already ending).

### 4.4 Commit and cancel

```cpp
ITfComposition* comp = m_pComposition;
m_pComposition = nullptr;           // I2
if (comp) {
    comp->EndComposition(ec);
    comp->Release();
}
```

The sink, if invoked during `EndComposition`, sees `m_pComposition == nullptr` and must not double-release.

### 4.5 Sink

```cpp
STDMETHODIMP OnCompositionTerminated(TfEditCookie ecWrite, ITfComposition* pComposition) {
    if (pComposition != m_pComposition) return S_OK; // stale / already handled
    m_pComposition = nullptr;                         // do NOT Release: the framework owns this termination
    m_isComposing = false;
    if (!m_isTerminating && m_pEngine) borno_engine_reset(m_pEngine);
    HideCandidates();
    return S_OK;
}
```

**Important:** the sink must not call `Release()` on `pComposition` unless the adapter still owns a reference that was not released elsewhere. Keep the ownership rule explicit in a comment: *the adapter owns exactly one reference while `m_pComposition != nullptr`.*

### 4.6 Destruction

- `Deactivate` must have ended or terminated the composition.
- The destructor should `assert(m_pComposition == nullptr)` in debug builds and otherwise only release the stored context reference.
- If the assertion fires in testing, the lifecycle is still wrong; do not ship.

## 5. Implementation plan

### WP-4.1.1 — Lifecycle map

Produce the table from §3. No code changes.

### WP-4.1.2 — Helper + context tracking

Implement §4.1–4.2. Route commit, cancel, deactivate and focus change through the helper.

### WP-4.1.3 — Sink hardening

Implement §4.4–4.5 with the ownership comment and the `m_isTerminating` flag.

### WP-4.1.4 — Debug instrumentation

Add a debug-only state log (no typed content):

```
[borno] composition: start ctx=0x... comp=0x...
[borno] composition: end reason=commit ctx=... 
[borno] composition: terminated-by-framework ctx=...
```

Assert `m_pComposition == nullptr` at the end of `Deactivate` and in the destructor.

### WP-4.1.5 — Stress test

Manual: 50 cycles of

1. type `ami` (composition active),
2. switch window / click another document,
3. return, type again,
4. close the host window mid-composition.

Record: no crash, no stuck underline, no orphan candidate window, no GDI growth.

Build without registration:

```powershell
pwsh -File native/borno-tsf/build.ps1 -NoRunHarness
```

Manual scenarios (Notepad and Word):

1. Compose, click another window, return, compose again.
2. Compose, `Alt+Tab`, return.
3. Compose, close the document.
4. Compose, commit.
5. Compose, Escape.
6. Compose, switch input language.
7. Repeat each 10× and watch for a crash or a stuck “composing” state.

If a debugger is available, run under Application Verifier or a debugger with a break on `OnCompositionTerminated` to confirm the order.

## 11. Stop conditions

- `ITfContextOwnerCompositionServices` is unavailable on the tested Windows build → stop and choose a different termination strategy; do not ship a release-only path.
- The framework calls the sink synchronously from `EndComposition` on the tested build and the design cannot distinguish ownership → stop and redesign the ownership model with a per-composition token.
- A fix requires holding a context reference across threads → stop (TSF is STA).
