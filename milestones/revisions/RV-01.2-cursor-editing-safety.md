## 1. Why this revision exists

The phonetic editing path mixes **byte offsets** and **character indices**:

- `source_cursor` is treated as a byte offset when compared to `raw_buffer.len()` and returned from `map_target_to_source`:
  [`lib.rs:659`](../../crates/bornomala-core/src/lib.rs#L659), [`lib.rs:1286-1308`](../../crates/bornomala-core/src/lib.rs#L1286-L1308).
- The same value is used as a `Vec<char>` index and re-assigned with `len_utf8()`:
  [`lib.rs:1311-1316`](../../crates/bornomala-core/src/lib.rs#L1311-L1316) (`insert_char_at_cursor`)
  [`lib.rs:1327-1335`](../../crates/bornomala-core/src/lib.rs#L1327-L1335) (`delete_before_cursor`)
  [`lib.rs:1347-1352`](../../crates/bornomala-core/src/lib.rs#L1347-L1352) (`delete_after_cursor`)

**Traced failure (reproduce it before fixing):**

1. `EngineEvent::InputString("৩৪")` → `raw_buffer = "৩৪"` (6 UTF-8 bytes, 2 chars), `source_cursor = 4` (wrong unit).
2. `MoveCursorLeft` → `source_cursor = 3`.
3. `Backspace` → `chars.len() == 2`, `remove_idx = 2`, condition `remove_idx < chars.len()` is false → **nothing deleted**; `source_cursor` becomes 0; the event returns `handled = true`.

For ASCII, byte length equals char count, so every existing test passes. The bug only appears for non-ASCII raw buffers — which is exactly what paste and some IME paths produce.

**Why this is P0:** silent text corruption inside the host application, combined with a false `handled` acknowledgement.

## 3. Scope

### Goals

1. One explicit unit per variable, enforced by the type system where practical.
2. Editing operations (insert, backspace, delete, cursor move) correct for arbitrary UTF-8 content in `raw_buffer`, including Bangla and mixed script.
3. A property-based regression suite that would have caught the original bug.
4. No performance regression on the ASCII typing path.

### Non-goals

- Do not redesign span mapping (RV-07).
- Do not add selection/word-delete features.
- Do not change the FFI layout (RV-02 owns the ABI; this revision only fixes semantics).
- Do not change `cursor_pos` from codepoints — native adapters depend on it.

### Explicit no-go

- **No** “clamp and continue”. Silent clamping is what hides the bug today; invalid indices must be impossible by construction or debug-asserted.
- **No** byte-index arithmetic on `Vec<char>` or char-index arithmetic on `String` outside a single conversion helper.
- **No** new dependency unless it replaces hand-written unsafe logic and passes the licence check.

## 4. Design decision required (choose before coding)

Two acceptable implementations:

### Option A — Newtypes (preferred for future-proofing)

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
pub struct BytePos(usize);
#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
pub struct CharPos(usize);

impl BytePos { pub fn from_str_end(s: &str) -> Self; pub fn to_char_pos(self, s: &str) -> CharPos; }
impl CharPos { pub fn to_byte_pos(self, s: &str) -> BytePos; }
```

- `source_cursor: CharPos` (or `BytePos`) — pick one and convert at the boundary.
- `raw_buffer` edits go through `String::insert`/`remove` at a verified byte boundary.

### Option B — Single canonical unit + conversion helpers (smaller diff)

- Keep `usize`, but rename the field to `source_cursor_chars: usize` and make `map_target_to_source` return a **char index**, converting at the `String` boundary with `char_indices().nth()`.
- Add `debug_assert!(raw_buffer.is_char_boundary(byte))` at every slice.

**Decision rule:** if the newtype change stays under ~15 files and the public API is unchanged, take Option A. If it would force changes in the C ABI or the UI contract in this revision, take Option B and leave a TODO for RV-02.

Record the decision and the rationale in `docs/design/index-units.md`.

## 5. Implementation plan

### WP-1.2.1 — Prove the bug

Add a failing test (commit it with the fix, not before):

```rust
#[test]
fn paste_bangla_then_backspace_deletes_one_character() {
    let mut e = BornoEngine::new();
    e.set_enable_dictionary_assistance(false);
    e.process_event(EngineEvent::InputString("৩৪".into()));
    e.process_event(EngineEvent::MoveCursorLeft);
    let r = e.process_event(EngineEvent::Backspace);
    assert_eq!(r.state.raw_buffer, "৩");
    assert_eq!(r.state.is_composing, true);
}
```

Run it. It must fail for the reason described in §1 (not a different reason). Record the failure output.

### WP-1.2.2 — Introduce the unit model

- Add the newtypes or the renamed field + conversion helpers.
- Convert every producer/consumer identified in the Index Unit Map.
- Add `debug_assert` invariants:
  - `cursor <= raw_buffer.chars().count()`
  - `raw_buffer.is_char_boundary(byte_offset)` at every slice
  - `spans` are sorted and non-overlapping

### WP-1.2.3 — Rewrite the three edit functions

For each of `insert_char_at_cursor`, `delete_before_cursor`, `delete_after_cursor`:

- Convert the cursor to the buffer's unit once, at the top.
- Assert bounds.
- Perform the edit.
- Recompute `cursor_pos` through the documented mapping.
- Return whether the buffer actually changed; `handled` must reflect it.

Also audit `Backspace`/`Delete` dispatch conditions ([`lib.rs:633-676`](../../crates/bornomala-core/src/lib.rs#L633-L676)) so they compare the correct unit.

### WP-1.2.4 — Fix `InputString`

`InputString` currently inserts char-by-char, recomputing composition each time. For this revision:

- Keep the per-char insert (performance is RV-07), but ensure the cursor ends at the correct char position for non-ASCII input.
- Add a test for a 200-character mixed-script `InputString` that asserts final buffer, cursor and no panic.

### WP-1.2.5 — Property tests

Add `crates/bornomala-core/tests/editing_properties.rs` using `proptest` (dev-dependency; justify it in the commit — it is the standard Rust property-testing crate, MIT/Apache-2.0).

Properties over generated mixed ASCII/Bangla strings:

1. Inserting then deleting the same char returns the original buffer.
2. Cursor never exceeds char count.
3. Backspace at 0 is a no-op and returns `handled = false`.
4. Delete at end is a no-op.
5. Moving left N times then right N times restores the cursor.
6. Every committed preedit is valid UTF-8 and NFC-stable.

If adding `proptest` is rejected, implement a deterministic table-driven property test over a fixed corpus of 200 generated cases committed as a fixture.

### WP-1.2.6 — Audit every `source_cursor` use

```powershell
Select-String -Path crates\bornomala-core\src\lib.rs -Pattern 'source_cursor'
```

Every occurrence must be reviewed and classified in the Index Unit Map. No exceptions.
