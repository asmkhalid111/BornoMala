## 1. Why this revision exists

The production candidate generator contains literal-input branches whose only purpose is to satisfy tests:

- [`crates/bornomala-core/src/phonetic/candidates.rs:27-28`](../../crates/bornomala-core/src/phonetic/candidates.rs#L27-L28):
  `if raw_buffer == "tumi" { push("তূমি") }` — `তূমি` is not a valid Bangla word and is not produced by any rule.
- [`crates/bornomala-core/src/phonetic/candidates.rs:73-80`](../../crates/bornomala-core/src/phonetic/candidates.rs#L73-L80):
  a block literally commented `// Backward Compatibility Fixtures for Engine Contract Tests` that pushes `খ` for `k`, and `ক্যা` + `খা` for `ka`.

The tests then assert these values as product behaviour:

- [`tests/contract_tests.rs:148-151`](../../crates/bornomala-core/tests/contract_tests.rs#L148-L151) asserts `["কা", "ক্যা", "খা"]` for `ka`.
- [`tests/engine_config_tests.rs:15-31`](../../crates/bornomala-core/tests/engine_config_tests.rs#L15-L31) asserts exactly 3 candidates for `ka` and slices those 3.

**Root cause:** during M1 the rule engine was not complete, so fixtures were added to make contract tests deterministic. They were never removed. The result is a closed verification loop: fabricated output is asserted by tests that are cited as evidence.

**Why this is P0:** `AGENTS.md` §1.3 forbids decorative/mock components that pretend to be functional. Candidate generation is the product's primary UX. Every future candidate feature would be built on a test suite that certifies fake data.

## 3. Scope

### Goals

1. Delete both literal-input branches from `CandidateGenerator::generate_candidates`.
2. Re-baseline every test that depended on them onto **rule-derived** candidates.
3. Add a regression test that would fail if literal-input special-casing returns.
4. Leave candidate ordering, the 5-candidate cap, NFC normalisation, and Slot 0 semantics unchanged.

### Non-goals

- Do not redesign the candidate ranking algorithm (that is RV-07).
- Do not add new rules or new candidates.
- Do not change the dictionary pipeline.
- Do not change the `EngineState` contract.

### Explicit no-go

- **No** “keep the fixture behind `#[cfg(test)]`”. The engine under test must be the engine that ships.
- **No** “make the test input produce the old output by changing the rules”. Rules change only with linguistic justification and their own test.
- **No** deletion of tests without a replacement assertion.

---

## 4. Design constraints

1. `generate_candidates(raw_buffer, primary)` must be a pure function of its inputs and the pinned rule tables. No input-specific `if` is allowed.
2. Candidate 0 remains the NFC-normalised primary transliteration.
3. The cap remains 5, and `push_if_unique` behaviour is unchanged.
4. ASCII-only raw buffers remain the only input to the phonetic path (this revision does not extend it).

## 5. Implementation plan (ordered work packages)

### WP-1.1.1 — Record the real baseline

- Add a **temporary** probe test (not committed) or use an existing test with `--nocapture` to print candidate lists for the eight inputs above.
- Save the output in `docs/evidence/RV-01.1/…` as the “before” state.
- Confirm each fabricated value appears only because of the literal branches: temporarily comment the branches out, re-run the probe, observe the difference. Restore the file.

**Gate:** the probe output is recorded and the difference is explained.

### WP-1.1.2 — Remove the branches

Delete:

- the `if raw_buffer == "tumi" { … } else if raw_buffer.ends_with('i')` special case, restoring the intended shape:
  ```rust
  if raw_buffer.ends_with('i') {
      // ALT-1: replace trailing ি with ী
  } else if raw_buffer.ends_with('u') {
      // ALT-1: replace trailing ু with ূ
  }
  ```
- the whole `// Backward Compatibility Fixtures …` block.

Do not “improve” the `u` branch, the ALT-2 rules, or the comments beyond what is needed.

**Gate:** `cargo test -p bornomala-core` compiles; expect the two dependent tests to fail. That failure is the proof the branches were real.

### WP-1.1.3 — Re-baseline the contract test

`test_candidate_navigation_wrapping_and_selection` needs a deterministic input with **at least three rule-derived candidates** (or the test must be restructured).

Preferred approach:

1. Choose an input whose rules genuinely generate ≥3 candidates. Verify it with the probe.
2. If no such short input exists, **restructure the test**:
   - Assert navigation with the real candidate count (1, 2, …), or
   - Inject candidates through the documented dictionary path with a small test lexicon fixture, or
   - Split the test into “navigation with 1 candidate”, “navigation with 2 candidates”, “selection index handling”, instead of assuming 3.

Forbidden: re-adding a production branch, or using `#[cfg(test)]` to fake the list.

**Gate:** the test asserts real output and still covers `NextCandidate`, `PrevCandidate`, direct selection, wrapping, and invalid index.

### WP-1.1.4 — Re-baseline the slicing test

`test_engine_candidate_display_limit_presentation_slicing` currently assumes 3 candidates for `ka`.

- Rewrite it around an input that genuinely has ≥3 candidates (probe-verified), or
- Split it: “limit 1 on a multi-candidate input”, “limit 2”, “limit larger than count”.

Also assert the documented behaviour that raising the limit does not restore truncated candidates until the next composition event; if that is undesirable, file it under RV-07 and do **not** change it here.

**Gate:** the test passes with real counts and still proves slicing.

### WP-1.1.5 — Add the anti-regression test

Add `crates/bornomala-core/tests/candidate_provenance_tests.rs` with:

1. **Primary invariant:** for ~50 common inputs, `candidates[0] == unicode::normalize_nfc(transliterate(raw).0)`.
2. **Cap invariant:** `candidates.len() <= 5`, no duplicates.
3. **No-fabrication invariant:** every candidate beyond index 0 must be reproducible by one of:
   - the ALT-1 trailing-vowel transform,
   - the ALT-2 sibilant transform,
   - the dictionary/ambiguity layer (identified by `CandidateKind`).
   Implement this as an explicit re-computation, not by calling the same function.
4. **Literal-guard test (source-level, optional but recommended):** read `candidates.rs` at test time with `include_str!` and assert it contains no `raw_buffer == "` comparison. This is a cheap tripwire against reintroduction; keep the message explanatory.

**Gate:** the new tests pass; deleting a rule makes at least one fail.

### WP-1.1.6 — Verify user-visible behaviour

Run the sandbox (`npm run tauri dev` or the portable exe) and confirm:

- Typing `ka` shows `কা` first and no `ক্যা`/`খা` fabrication.
- Typing `k` shows `ক` first and no `খ`.
- Typing `tumi` shows `তুমি` first and `তুমী` as the ALT-1 alternate; `তূমি` is absent.

Screenshot or record the candidate panel for the evidence file.

**Gate:** manual observation recorded.
