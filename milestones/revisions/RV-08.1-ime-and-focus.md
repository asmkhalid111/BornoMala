## 1. Why this revision exists

The sandbox's only input is a controlled `<input>` with a no-op `onChange`, and the keydown handler has no composition guard:

- [`SandboxTypingArea.tsx:591-592`](../../src/components/SandboxTypingArea.tsx#L591-L592) — `value={engineState.raw_buffer}` with `onChange={() => {}}`.
- [`SandboxTypingArea.tsx:316-407`](../../src/components/SandboxTypingArea.tsx#L316-L407) — no `e.isComposing`/keyCode 229 check; every printable key is `preventDefault`ed.
- No `compositionstart`/`compositionupdate`/`compositionend` and no `onPaste` anywhere in `src/` (grep-verified).

**Consequences:**

1. With any system IME active (including Borno's own TSF when installed), `e.key` is often `"Process"`/`"Unidentified"`; the engine receives nothing, and composed text can be wiped by the next state render.
2. Pasting text into the field does nothing.
3. Clicking a virtual key, candidate, mode button, or the settings button moves focus away from the input; physical typing then silently stops until the user clicks back.

This revision makes the sandbox a reliable test surface for the engine — which is its stated purpose in the roadmap.

## 3. Scope

### Goals

1. No text loss when a system IME is active.
2. Paste works and is routed to the engine.
3. Focus is retained across mouse interactions with sandbox controls.
4. A clear, honest notice when a system IME is interfering.
5. Automated tests for all three behaviours.

### Non-goals

- No changes to the native TSF/Fcitx adapters.
- No new candidate UI.
- No full text editor (this is a capture field, not a document).

### Explicit no-go

- **No** `preventDefault` on keys while `isComposing` is true.
- **No** controlled input with a no-op `onChange` without a composition strategy.
- **No** silently dropping pasted text.
- **No** document-level key capture that steals keys from other inputs (settings fields must keep working).

---

## 4. Design decisions

### 4.1 Foreign IME policy (decide before coding)

The sandbox exists to test **Borno's** engine. If another IME is active, two reasonable policies:

**Policy A — Verbatim passthrough (recommended):** on `compositionend`, take `event.data` and append it directly to the committed output, bypassing transliteration, with a small notice: “Foreign IME input committed verbatim.” This preserves user text and keeps the sandbox honest about what it tested.

**Policy B — Ignore + warn:** on `compositionstart`, show “A system IME is active; switch to English to test Borno.” Do not insert the composed text.

Pick A unless the developer prefers B. Record the decision in the code comment and evidence file.

### 4.2 Input element strategy

Recommended: keep a **controlled** input for display but suspend syncing while composing:

```tsx
const composingRef = useRef(false);
// value={composingRef.current ? undefined : engineState.raw_buffer}  // uncontrolled during composition
```

Alternative: use an uncontrolled input and clear it after each dispatched event; render preedit separately (the sandbox already does).

Choose one and test both the normal and composition paths. Do not leave the field as a dead controlled input.

### 4.3 Focus retention

- Add `useTypingFocus()` that exposes `focusInput()` and a `typingActive` flag.
- After candidate click, virtual key click, mode change, or settings close → `focusInput()`.
- Do **not** install a global `keydown` listener that would capture typing while the settings drawer or a text field is focused.
- When the settings drawer opens, typing capture is suspended; on close, focus returns to the input.

### 4.4 Paste

- `onPaste`: `preventDefault()`, read `text/plain`, dispatch `InputString`.
- Also support `beforeinput` with `inputType: "insertFromPaste"` for WebView2.
- Guard against extremely large pastes (e.g. >2,000 chars): chunk or ask for confirmation; record the behaviour.

## 5. Work packages

### WP-8.1.1 — Extract the input hook

Move key handling into `useEngineInput()` with explicit states:

```
idle | composing(foreign) | capturing
```

Gate: component shrinks; behaviour unchanged for ASCII.

### WP-8.1.2 — Composition handling

- `onCompositionStart`: set `composing=true`, stop syncing the controlled value.
- `onCompositionUpdate`: optional; keep the latest data in a ref.
- `onCompositionEnd`: set `composing=false`, apply the §4.1 policy, refocus.
- `keydown`: if `e.nativeEvent.isComposing || e.keyCode === 229` → return without `preventDefault`.

Gate: with a Japanese IME, typing `あ` does not lose text; with Borno TSF active, the sandbox shows the notice and does not double-insert.

### WP-8.1.3 — Paste

Implement §4.4 and a test with a mocked `ClipboardEvent`.

Gate: pasting `আমি` and `ami` both behave per policy (Bangla verbatim; ASCII transliterated).

### WP-8.1.4 — Focus retention

Implement §4.3 and wire every interaction listed. Add a visible “typing paused” hint if focus left the input.

Gate: click a candidate, then type — characters continue.

### WP-8.1.5 — Automated tests

Vitest + Testing Library:

1. `fireEvent.compositionStart` + `compositionEnd` → no key dispatch during composition; data handled per policy.
2. `fireEvent.paste` → `InputString` dispatched once.
3. Click candidate → input has focus again.
4. Click virtual key → focus returns.
5. Settings open → typing suspended; close → focus restored.
6. Rapid type + click does not drop characters (queue from RV-07.3).

Gate: tests pass and fail when the guard is removed.
