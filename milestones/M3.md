## 1. Milestone Purpose, Scope & Architectural Boundaries

### 1.1 Purpose
Replace the minimal M0 deterministic transliteration stub (`crates/borno-core/src/translit.rs`) with a comprehensive, production-grade, Avro-compatible phonetic input engine in the pure Rust core (`crates/borno-core/src/phonetic/`).

### 1.2 Strict Scope Separation: M3 (Deterministic Transliteration) vs. M6 (Dictionary & Correction)
A critical pitfall in Bengali input systems is conflating **phonetic transliteration** (mapping sound sequences to letters, vowel signs, and conjuncts) with **dictionary-backed autocorrection and statistical frequency prediction**. This plan strictly enforces the architectural boundaries established in `ROADMAP.md`:

```
┌────────────────────────────────────────────────────────────────────────┐
│ MILESTONE M3 SCOPE (This Milestone)                                    │
│ - Deterministic phonetic tokenizer and contextual rule matching.       │
│ - Avro-compatible phonetic mapping tables (vowels, consonants,         │
│   curated conjunct matrix, phalas, modifiers, and backtick controls).   │
│ - Bounded, rule-based candidate generation (explicit phonological      │
│   alternatives; strictly no word-specific dictionary overrides).       │
│ - Bidirectional source-to-target span and cursor mapping contract.     │
│ - Integration with M1 engine contract & M2 Unicode NFC pipeline.       │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ Outputs feed into
┌───────────────────────────────────▼────────────────────────────────────┐
│ MILESTONE M6 SCOPE (Deferred — Future Milestone)                       │
│ - 150,000+ word dictionary / lexicon corpus and prefix trie.           │
│ - Word-specific spelling corrections (e.g. autocorrecting khoma→ক্ষমা).│
│ - Frequency-based candidate ranking and statistical n-gram scoring.    │
│ - Automatic spell-checking, typo correction, and fuzzy matching.       │
│ - User dictionary customization and word learning.                     │
└────────────────────────────────────────────────────────────────────────┘
```

- **M3 delivers:** A deterministic, rule-based phonetic engine where Candidate 0 is the exact primary phonetic transliteration, and Candidates 1..N represent explicit, tested **orthographic spelling alternatives** (e.g. `ami` generating `["আমি", "আমী"]`), with known false-positive over-generations explicitly documented and a single consistent cap of **maximum 5 candidates total** (Candidate 0 plus at most 4 alternates).
- **M3 does NOT include word-specific dictionary aliases:** In Avro Keyboard, word transformations like `khoma` → `ক্ষমা` or `biggan` → `বিজ্ঞান` stem exclusively from dictionary lookup and autocorrect tables (`autocorrect.js`), not general phonetic rules. In a deterministic rule-based transliteration engine without a dictionary:
  - `khoma` transliterates directly to Candidate 0: `খমা` (`খ` + `ম` + `া`). To produce `ক্ষমা`, the phonetic spelling is `kShoma` or `xoma`.
  - `biggan` transliterates directly to Candidate 0: `বিগ্গান` (`ব` + `ি` + `গ` + `্` + `গ` + `া` + `ন`). To produce `বিজ্ঞান`, the phonetic spelling is `bijNGan` or `bijgyan`.
  - Admitting word-specific overrides into M3 would create a hidden, unprincipled dictionary. Therefore, all word-specific aliases and dictionary-assisted autocorrection are strictly deferred to **Milestone M6**.

## 3. Pinned Avro Reference Baseline & Evidence-Based Licensing Assessment

### 3.1 Pinned Reference Artifacts
To eliminate ambiguous claims of "Avro compatibility," Borno pins its phonetic transliteration specification to verifiable open-source artifacts and official documentation:
- **Primary Reference Implementation:** OmicronLab `pyAvroPhonetic` at pinned commit `8a9277f` (ported from Rifat Nabi's `jsAvroPhonetic`).
  - *Artifact Structure & Location:* Package name is `pyavrophonetic/` (all lowercase); phonetic replacement patterns are defined in `pyavrophonetic/resources/avrodict.json` and loaded by `pyavrophonetic/config.py`. Contextual predicates (`isVowel`, `isConsonant`, `isExact`, `isPunctuation`) reside in `pyavrophonetic/utils/`.
- **Secondary Reference Implementation:** `sarim/ibus-avro` at pinned commit `40947fa`.
  - *Artifact Structure & Location:* Core files reside at repository root (`avrolib.js`, `avrodict.js`, `autocorrect.js`, `avroregexlib.js`, `Makefile.am`). The transliteration engine and replacement pattern definitions reside directly in `avrolib.js`, whereas `avrodict.js` contains the dictionary suggestion database and `autocorrect.js` contains word-specific spelling exception overrides.
- **Reference Output Corpus:** Official OmicronLab Avro Keyboard 5.6.0 user documentation test vectors (`avro_phonetic_help.html`, 85 documented reference mappings).
- **Separation of Grammar vs. Lexicon:** In the pinned references, pattern arrays with prefix/suffix context predicates define classic deterministic phonetic transliteration. In contrast, dictionary tries (`avrodict.js`) and spelling overrides (`autocorrect.js`) define dictionary lookup and typo correction, which are explicitly excluded from M3 and deferred to M6.

## 4. Audited & Classified Rule Tables

Every mapping in this section is classified into one of three explicit categories:
- **`[Avro-Compatible]`**: Grounded directly in the published Avro Phonetic v5.x grammar and documentation (`avro_phonetic_help.html`).
- **`[Borno Extension]`**: Explicit additions or enhancements introduced by Borno (e.g. `\t` escape for Khanda-Ta, backtick virama ```).
- **`[Unresolved / Under Evaluation]`**: Divergent behavior across reference implementations requiring explicit resolution before implementation.

> [!NOTE]
> **Tokenizer Sibilant Precedence Rules & Conjunct Disambiguation:**  
> Greedy longest-prefix matching resolves sibilant clusters in the following deterministic order:  
> 1. Trigraphs & 4-graphs: `ShTh` (len 4) → `ষ্ঠ` (`\u{09B7}\u{09CD}\u{09A0}`), `sTh` (len 3) → `স + ্ + ঠ` (`\u{09B8}\u{09CD}\u{09A0}`), `ShT` / `shT` (len 3) → `ষ্ট` (`\u{09B7}\u{09CD}\u{099F}`), `sht` (len 3) → `শ্ত` (`\u{09B6}\u{09CD}\u{09A4}`).  
> 2. Digraphs (len 2):  
>    - `sT` → `স্ট` (`\u{09B8}\u{09CD}\u{099F}`, dental sibilant `স` + virama + retroflex `ট`, matching before single-character `s`).  
>    - `ST` → `ষ্ট` (`\u{09B7}\u{09CD}\u{099F}`, retroflex sibilant `ষ` + virama + retroflex `ট`).  
>    - `st` → `স্ত` (`\u{09B8}\u{09CD}\u{09A4}`, dental sibilant `স` + virama + dental `ত`).  
>    - `St` → `শ্ত` (`\u{09B6}\u{09CD}\u{09A4}`, palatal sibilant `শ` + virama + dental `ত`).  
>    - `sh` → `শ` (`\u{09B6}`), `Sh` → `ষ` (`\u{09B7}`).  
> 3. Single letters (len 1): `s` → `স` (`\u{09B8}`), `S` → `শ` (`\u{09B6}`), `t` → `ত` (`\u{09A4}`), `T` → `ট` (`\u{099F}`).
> 
> **Resolution of `NG` vs `ঞ্জ` Token Disambiguation:**  
> In Avro and Borno, single letter `ঞ` (`U+099E`) is triggered exclusively by `NG` (e.g. `miNGa` → `মিঞা`). The alias `Nj` is completely eliminated to prevent token collision with the conjunct `ঞ্জ`.  
> The conjunct `ঞ্জ` (`U+099E U+09CD U+099C`) is triggered by `NGj` or `nj` (e.g. `goNGj` / `gonj` → `গঞ্জ`, `guNGjon` → `গুঞ্জন`).

### 4.4 Phalas, Modifiers, and Special Key Sequences

1. **Reph (রেফ):**
   - Trigger: `r` preceding a consonant (e.g. `rk` → `র্ক`, `rb` → `র্ব`, `rm` → `র্ম`, `rSh` → `র্ষ`). `[Avro-Compatible]`
   - Unicode sequence: `\u{09B0}\u{09CD}` followed by the target consonant.
2. **Ra-phala (র-ফলা):**
   - Trigger: Consonant followed by `r` (e.g. `kr` → `ক্র`, `gr` → `গ্র`, `pr` → `প্র`, `tr` → `ত্র`, `br` → `ব্র`). `[Avro-Compatible]`
   - Unicode sequence: Consonant + `\u{09CD}\u{09B0}`.
3. **Ya-phala (য-ফলা):**
   - Trigger: Consonant followed by `y` or `Z` (e.g. `ky` / `kZ` → `ক্য`, `by` → `ব্য`, `ny` → `ন্য`, `ty` → `ত্য`, `bakyo` → `বাক্য`). `[Avro-Compatible]`
   - Unicode sequence: Consonant + `\u{09CD}\u{09AF}`.
4. **Ba-phala (ব-ফলা):**
   - Trigger: Consonant followed by `w` or `v` (e.g. `sw` / `sv` → `স্ব`, `dw` → `দ্ব`, `kw` → `ক্ব`). `[Avro-Compatible]`
   - Explicit Distinction: Consonant followed by `b` produces a standard consonant conjunct with `ব` (e.g. `shobdo` → `শব্দ`, `sombol` → `সম্বল`), whereas `w` and `v` produce the subjoined Ba-phala (`swadhin` → `স্বাধীন`, `biswo` → `বিশ্ব`).
5. **Khanda-Ta (`ৎ`, `U+09CE`):**
   - Trigger: `t`` (e.g. `ut`shob` → `উৎসব`, `hot`ath` → `হঠাৎ`). `[Avro-Compatible]`
   - Extension Alias: `\t` escape sequence. `[Borno Extension]`
6. **Candrabindu (`ঁ`, `U+0981`):**
   - Trigger: `^` (caret) or `N` in nasal suffix context (e.g. `c^ad` → `চাঁদ`, `b^aTi` → `বাঁটি`). `[Avro-Compatible]`
7. **Explicit Hasanta / Virama (`্`, `U+09CD`):**
   - Trigger: `,,` after a consonant suppresses the inherent vowel without creating a conjunct (e.g. `k,,` → `ক্`). `[Avro-Compatible]`
   - Backtick Virama: Backtick ``` after a consonant (`k``` → `ক্`). `[Borno Extension]`
8. **Token Boundary Disambiguation (Backtick ` `):**
   - The backtick key ``` breaks greedy multi-character pattern matching: `[Avro-Compatible]`
     - `eki` → `একি` (`e` + `k` + `i`), but `ek`\`i` → `একই` (`e` + `k` + break + independent `i`).
     - `poth` → `পথ` (`p` + `th`), but `pot`\`h` → `পোতহ`.

## 5. Bidirectional Source-to-Target Cursor Mapping Contract

In Milestone M2, cursor remapping handled internal scalar adjustments after normalization. Milestone M3 defines the formal contract mapping **source coordinates in Latin ASCII `raw_buffer` to target coordinates in Bangla Unicode `preedit`**.

### 5.1 Coordinate Units & Span Tracking
- **Source Coordinate Unit:** 0-indexed byte offset ($S \in [0, \text{raw\_buffer.len()}]$) in ASCII `raw_buffer`.
- **Target Coordinate Unit:** 0-indexed Unicode scalar value (codepoint) offset ($T \in [0, \text{preedit.chars().count()}]$) in Bangla `preedit`.
- **Token Span Map:** During parsing, the tokenizer produces a sequence of contiguous spans:
  ```rust
  pub struct TokenSpan {
      pub source_range: std::ops::Range<usize>, // byte range [start, end) in raw_buffer
      pub target_range: std::ops::Range<usize>, // codepoint range [start, end) in preedit
  }
  ```

### 5.2 Cursor Mapping Rules & Intermediate Affinity
1. **End-of-Buffer Rule:** When typing sequentially ($S == \text{raw\_buffer.len()}$), the target cursor is placed at the end of the preedit ($T = \text{preedit.chars().count()}$).
2. **Token Boundary Rule:**
   - If $S == \text{token.source\_range.start}$, then $T = \text{token.target\_range.start}$.
   - If $S == \text{token.source\_range.end}$, then $T = \text{token.target\_range.end}$.
3. **Interior Multi-Character Token Rule (Left Affinity):** When source cursor $S$ sits strictly inside a multi-character token ($token.source\_range.start < S < token.source\_range.end$):
   - The target cursor maps to `token.target_range.start`.
   - *Rationale:* Multi-byte Latin digraphs/trigraphs (e.g. `kh`, `kSh`, `Ng`) map to atomic Bangla characters or complex ligatures that cannot be split visually without corrupting grapheme cluster integrity.
4. **Retokenization & Deletion Rule:**
   - When an interior insertion or deletion modifies the text (e.g. deleting `S` from `kSh`), the containing word is greedily retokenized from the left word boundary.
   - The new target cursor position $T$ is computed by evaluating the updated source offset $S$ against the newly generated `TokenSpan` list.
5. **Post-NFC Scalar Clamping:** The target cursor position is passed through M2's `unicode::remap_cursor_position`, ensuring canonical composition (e.g. two-part vowels `ে` + `া` → `ো`) clamps the cursor to a valid scalar boundary.

### 5.2.1 Post-NFC Span Realignment Contract
When NFC normalization alters the Unicode scalar count of the target composition string (such as canonical composition collapsing two-part vowel signs `ে` + `া` into atomic O-kar `ো`, decreasing scalar count by 1, or strict NFC decomposition expanding nukta-derived consonants into base + nukta, increasing scalar count by 1), the engine applies an **NFC Span Realignment Pass** to keep all `TokenSpan`s valid:
1. **Remapping Monotonicity:** Each token's target boundaries are passed through M2's `unicode::remap_cursor_position`:
   - `token.target_range.start = unicode::remap_cursor_position(token.raw_target_range.start)`
   - `token.target_range.end = unicode::remap_cursor_position(token.raw_target_range.end)`
2. **Cumulative Delta Tracking:** Because `remap_cursor_position` tracks cumulative scalar offsets resulting from compositions/decompositions, all downstream token boundaries automatically shift in lockstep with the normalized string.
3. **Internal Collapse Clamping:** If multiple scalars inside a single token's target range collapse into fewer scalars (e.g. 2 scalars into 1), the token's normalized `target_range` length contracts accordingly, and any raw interior index is clamped to the start boundary of the composite scalar.

     - Clamping Safety: If a raw pre-NFC interior index $T_{raw} = 2$ (between decomposed `ে` and `া`) is evaluated, `remap_cursor_position` clamps $T$ to 1 (before `"ো"`), ensuring cursor never lands on a nonexistent scalar boundary inside composite `"ো"`.

## 6. Bounded, Linguistically Defensible Candidate Generation

To keep M3 deterministic without expanding into M6's dictionary domain, candidate generation is strictly bounded:

### 6.1 Explicit Orthographic Spelling Alternatives (No Blanket Replacements)
Blanket substitutions (such as unconditionally replacing every `ি` with `ী`, or every `স` with `শ`/`ষ`) cause exponential Cartesian expansion and generate unpronounceable gibberish. Furthermore, in standard modern spoken Bengali, short and long high vowels are phonologically identical (/i/ and /u/). Therefore, generating long-vowel variants represents **orthographic spelling alternation**, NOT a phonological distinction. M3 restricts alternate candidate generation to two explicit, tested rules whose conditions strictly match their examples:

1. **Rule ALT-1 (Word-Final Vowel Orthographic Alternation):**
   - Condition: When a word ends with an open high vowel `i` or `u`, generate exactly one alternate candidate with the corresponding long vowel `ী` or `ূ`:
     - `ami` → Candidate 0: `"আমি"`, Candidate 1: `"আমী"`.
     - `tumi` → Candidate 0: `"তুমি"`, Candidate 1: `"তূমি"`.
   - Medial vowels do not trigger automatic doubling.
   - *Documented False-Positive Over-Generation:* Under prescriptive modern Bangla Academy orthography, pronouns like `আমি` and `তুমি` only permit `আমি` and `তুমি`. Generating `"আমী"` or `"তূমি"` is an acknowledged orthographic false-positive over-generation of non-lexical rule expansion. However, the rule is maintained and tested to allow legitimate alternate/historical spellings in words like `baRi` (`["বাড়ি", "বাড়ী"]`), `pakhi` (`["পাখি", "পাখী"]`), and `ali` (`["আলি", "আলী"]`) without requiring a dictionary in M3.
2. **Rule ALT-2 (Sibilant Orthographic Alternation: Palatal / Dental / Retroflex):**
   - **Rule ALT-2a (Initial Sibilant Homophone Alternation):**
     - Condition: When a word begins with initial `sh` followed by vowel `a` and a dental nasal or stop (`nt`, `nd`, `n`):
       - `shanto` → Candidate 0: `"শান্ত"` (`[Avro-Compatible]`, primary transliteration `sh` → `শ`), Candidate 1: `"সান্ত"` (dental sibilant alternate `স`).
   - **Rule ALT-2b (Medial Sibilant Cluster Alternation):**
     - Condition: When input contains `s` followed by retroflex stop `T` or `Th` (e.g. `sT` / `sTh`):
       - `kosTo` → Candidate 0: `"কস্ট"` (`[Avro-Compatible]`, direct transliteration: `k` + `o` + `sT` + `o` → `ক` + `স` + `্` + `ট` = `"কস্ট"`, exact codepoint sequence `\u{0995}\u{09B8}\u{09CD}\u{099F}`, standard for loanwords like `স্টেশন`).
       - Candidate 1: `"কষ্ট"` (retroflex cluster alternate `ষ` + `্` + `ট` = `"কষ্ট"`, exact codepoint sequence `\u{0995}\u{09B7}\u{09CD}\u{099F}`, standard for native Sanskrit/Tatsama words where users type ASCII `sT` instead of `ShT`/`ST`/`shT`).
     - *Contrast with Dental `st`:* When typing `kosto` (lowercase `t`), Candidate 0 is `"কস্ত"` (`স` + `্` + `ত`, `\u{0995}\u{09B8}\u{09CD}\u{09A4}`). Dental `t` never alternates to retroflex `ট`.

### 6.2 Strict Exclusion of Word-Specific Dictionary Overrides in M3
- **Candidate 0:** Always the exact, primary Avro-compatible deterministic transliteration.
- **No Word-Specific Aliases:** Word-specific substitutions (such as hardcoding `khoma` → `ক্ষমা` or `biggan` → `বিজ্ঞান`) are strictly rejected from M3. In M3:
  - `khoma` produces only Candidate 0: `"খমা"`. (To produce `"ক্ষমা"`, the user types `kShoma` or `xoma`).
  - `biggan` produces only Candidate 0: `"বিগ্গান"`. (To produce `"বিজ্ঞান"`, the user types `bijNGan` or `bijgyan`).
- **Ordering:** Alternate candidates follow deterministic rule priority (`ALT-1` > `ALT-2`).
- **Deduplication:** All candidates are passed through `unicode::normalize_nfc` and deduplicated.
- **Strict Single Candidate Cap:** Bounded at a maximum of **5 candidates total** (Candidate 0 plus at most 4 alternate candidates).
- **Single-Candidate Fallback:** If no alternate rule triggers, `EngineState.candidates` contains only `[candidate_0]` or is empty, maintaining 100% compliance with M1 contract test `test_candidate_empty_behavior`.

## 7. Performance Specification & Portable Benchmark Procedure

### 7.1 Quantitative Performance Criteria
- **Pure Core Latency (Release Profile - Gate Requirement):** Mean processing time per keystroke in pure Rust (`borno-core`) must be **< 0.5 ms** (budget: **< 1.0 ms**).
- **End-to-End Desktop UI Latency (Measured Target):** Full round-trip across Tauri IPC to WebView2 DOM update must remain **< 5.0 ms** target.
- **Algorithmic Complexity:** Token scanning and candidate generation must operate in linear time $O(N)$ with respect to input buffer length.

### 7.2 Portable Benchmark Harness & Measurement Separation
Timing measurements are strictly separated from functional correctness tests and keep pure Rust core performance distinct from Tauri IPC round-trips:
- **Functional Correctness Tests:** Run via standard `cargo test -p borno-core`.
- **Pure Core Release Benchmark:** Executed via a dedicated benchmark test in release profile using a portable command that does not depend on machine-specific absolute Windows paths:
  ```powershell
  cargo test -p borno-core --test phonetic_tests test_benchmark_keystroke_latency --release -- --nocapture
  ```
  *(Note: Relies on `cargo` available in system `PATH`; does not hardcode developer-specific drive letters or target directories).*
- **Benchmark Corpus:**
  1. *Short Tokens (1–5 chars):* `k`, `ka`, `ami`, `kor`, `boi`.
  2. *Medium Words (6–15 chars):* `bangladesh`, `bijNGan`, `kShoma`, `brriSTi`.
  3. *Long Sentences (50+ chars):* A representative paragraph of continuous Bengali typing.
- **Execution & Reporting:** 10,000 iterations in release profile, recording Min, Mean, Median (p50), 95th Percentile (p95), and 99th Percentile (p99) in microseconds ($\mu s$). Environment CPU, OS, and rustc version will be recorded in the completion report.
- **Desktop UI Latency Measurement Methodology:** End-to-end desktop UI latency (target < 5.0 ms) is measured separately inside the desktop sandbox using `window.performance.now()` instrumentation in `src/components/SandboxTypingArea.tsx`. Timing begins synchronously in the `onKeyDown` handler upon keystroke in the WebView2 DOM, traverses Tauri IPC to `process_event`, executes core engine processing, returns `ProcessResult`, reconciles React preedit/candidate state, and completes DOM render. Min, mean, median, and 95th percentile are recorded across continuous typing runs in the sandbox.

## 10. Stop Conditions & Risk Management

- **Regression Stop:** If any of the 60 baseline tests fail during M3 development, halt immediately and resolve before proceeding.
- **Scope Creep Stop:** If an implementation idea requires an external dictionary file, wordlist trie, or spell-check corpus, halt and defer it to Milestone M6.
- **Tokenizer Ambiguity Stop:** Multi-character consonant patterns must use greedy, longest-match-first matching to prevent exponential backtracking. Parsing time must remain strictly linear $O(N)$ relative to input length.
- **Rendering Boundary:** Do not emit custom font-specific ligatures or PUA codes. All transliteration output must remain pure, standard Unicode.
- **Execution Gate:** Milestone M3 is complete only when all 9 acceptance criteria are verified and its completion report is approved.
