## 1. Executive Summary & Purpose

Milestone M9 delivers comprehensive **customization, typing usability, linguistic ambiguity handling, and candidate presentation preferences** to the Borno Bangla Input Platform. It bridges the platform foundations completed in M7 (Windows TSF) and M8 (Linux Fcitx 5) with an adaptable, user-centric typing experience across all supported surfaces.

M9 directly resolves the **Usability and Linguistic Backlog** documented during live platform testing:
1. **Bengali Dáñṛi (`।`) and Double Dáñṛi (`॥`) Unicode Punctuation:** Corrects the punctuation emission branches in the phonetic tokenizer, provides deterministic longest-match period conversion (`..` $\to$ `।`, `....` $\to$ `॥`), and introduces a configurable preference for single-period conversion with reliable decimal and domain safeguards.
2. **Casual Vowel & Nasal Ambiguity:** Addresses high-frequency phonological ambiguities (`tomake` $\to$ `তোমাকে`, `bornomala` $\to$ `বর্ণমালা`) via bounded, lexicon-validated alternation rules without violating the primary transliteration invariant (Slot 0).
3. **Schema Evolution & Whitelist Migration (`BornoConfig` v1.2.0):** Defines an explicit version migration and invariant validation pipeline from legacy schemas (`1.0.0` and `1.1.0`), preventing configuration corruption upon upgrade.
4. **Transactional Persistence & Settings Synchronization:** Implements prepare-before-commit configuration transactions, atomic JSON import/export, and corruption recovery in the Tauri backend with automatic rollback and native adapter reload.
5. **Categorized Settings UI:** Upgrades the desktop Settings Drawer into a fully accessible, categorized interface with theme switching (`Dark Glass`, `Light Glass`, `High Contrast`), point-based font scaling, hotkey selection, and factory reset.
6. **Platform Alignment & C-ABI Delivery:** Specifies the C-ABI configuration delivery contract (`borno_engine_configure_json`) with composition preservation, and establishes an explicit capability matrix detailing which appearance and behavior settings each platform surface (Tauri Desktop, Windows TSF, Linux Fcitx 5) natively honors.

## 2. Baseline Architecture & Dependency Analysis

### 2.1 Configuration Subsystem & Historical Schemas

- **Supported Historical Versions:**

  - `1.1.0`: Added M6 dictionary assistance (`enable_dictionary_assistance`, `enable_word_completion`, `max_dictionary_suggestions`).
- **Persistence Path:**
  - Windows: `%APPDATA%\com.bornomala.desktop\config.json`
  - Linux: `~/.config/com.bornomala.desktop/config.json`
- **Current Persistence Mechanism:** [`src-tauri/src/config_store.rs`](../src-tauri/src/config_store.rs) handles safe replacement via temporary files (`.tmp`) and rename operations, preserving unsupported versions byte-for-byte untouched under `PersistenceStatus::LockedUnsupportedVersion`.
- **C-ABI Configuration Entry Point:** The core engine accepts configuration via `BornoEngine::with_config(config)`. The existing C ABI (`crates/bornomala-core/src/ffi.rs` and `include/bornomala.h`) exposes `borno_engine_new()` but lacks a configuration injection API. Phase 1 introduces `borno_engine_configure_json` to provide configuration delivery to native adapters.

### 2.2 Tokenizer & Buffer Processing
- **Buffer Mechanism:** [`crates/bornomala-core/src/phonetic/tokenizer.rs`](../crates/bornomala-core/src/phonetic/tokenizer.rs) operates as a greedy scanner over an accumulated `raw_buffer`. On each keystroke, the engine re-parses the full preedit buffer.
- **Source Inspection of Existing Punctuation Emission:**
  - Lines 128–150 of `tokenizer.rs` show:
    ```rust
    if rem.starts_with("||") { output.push('\u{09E5}'); ... }
    if rem.starts_with('|') { output.push('\u{09E4}'); ... }
    ```
  - Standard Bengali Danda (Dáñṛi `।`) is **`U+0964`**.
  - Standard Bengali Double Danda (Double Dáñṛi `॥`) is **`U+0965`**.
  - Pipe `|` and double pipe `||` erroneously emitted `\u{09E4}` and `\u{09E5}`.
  - Periods (`.`) currently fall through to Step 7 (ASCII passthrough).
- **Unicode Regression Policy:** `U+09E4` and `U+09E5` are assigned characters in the Bengali Unicode block. They must not be prohibited globally or banned across unrelated text. M9 specifically corrects the erroneous punctuation-emission branches in `tokenizer.rs` and tests those affected branches.

### 2.3 Ambiguity, Lexicon & Candidate Ranking
- **Ambiguity Engine:** [`crates/bornomala-core/src/dictionary/ambiguity.rs`](../crates/bornomala-core/src/dictionary/ambiguity.rs) generates phonetic raw variants and validates them against the embedded `PrefixTrie`.
- **PrefixTrie Exact-Word Lookup:**
  - Inspection of `PrefixTrie::get_frequency(&self, word: &str)` in [`crates/bornomala-core/src/dictionary/trie.rs`](../crates/bornomala-core/src/dictionary/trie.rs) (lines 134–145) confirms it performs **strictly exact-word lookup** (`curr.frequency > 0`). It returns `None` for internal prefix nodes that are not terminal word entries.
- **Primary Transliteration Behavior:**
  - In `rules.rs` (lines 160–172), lowercase `o` following a consonant is the inherent vowel bridge (`dependent: None`), while uppercase `O` maps to o-kar (`\u{09CB}`).
  - Direct transliteration of `tomake` strictly produces **`তমাকে`** in Candidate Slot 0.
  - In `rules.rs` (lines 168–186), `r` followed by consonant `n` emits `REPH_PREFIX` followed by dental `ন`, strictly producing **`বর্নমালা`** in Candidate Slot 0.
- **Lexicon Verification:**
  - Inspection of `crates/bornomala-core/data/lexicon.tsv` confirms:
    - `"তোমাকে"` is present (rank 8644, frequency 36).
    - `"বর্ণ"` is present (rank 13570, frequency 18), and `"বর্ণনা"` is present (rank 4057, frequency 105).
    - `"বর্ণমালা"` is currently missing from `lexicon.tsv`. In Phase 2, `"বর্ণমালা"` must be added to `lexicon.tsv` and compiled into `lexicon.bin` using `scripts/prepare_lexicon.py` so that production trie queries succeed.
- **Candidate Ranking & Deduplication:**
  - In [`crates/bornomala-core/src/dictionary/ranker.rs`](../crates/bornomala-core/src/dictionary/ranker.rs), candidates are ranked into strict deterministic tiers:
    - **Priority 0 (Candidate Slot 0):** `CandidateKind::PrimaryTransliteration`. Strictly immutable; never replaced by ambiguity or dictionary suggestions.
    - **Priority 1 (Candidate Slot 1):** `CandidateKind::ExactLexiconMatch`. Validated ambiguity matches. If an ambiguity match duplicates Candidate Slot 0, it is discarded by `push_candidate` deduplication and the next distinct candidate is evaluated.
    - **Priority 2:** `CandidateKind::PhoneticAlternative`.
    - **Priority 3:** `CandidateKind::PrefixCompletion`.
    - **Priority 4:** `CandidateKind::SpellingCorrection`.
- **Dictionary Isolation:** When `enable_dictionary_assistance` is `false`, ambiguity generation and trie lookups are completely bypassed, returning strictly Candidate Slot 0.

## 4. Detailed Behavioral Contracts

### 4.1 Punctuation Contract: Bengali Dáñṛi & Double Dáñṛi

#### 4.1.1 Codepoint Corrections in Tokenizer
In `crates/bornomala-core/src/phonetic/tokenizer.rs`:
- Pipe `|` branch: Emit `\u{0964}` (Bengali Dáñṛi `।`).
- Double pipe `||` branch: Emit `\u{0965}` (Bengali Double Dáñṛi `॥`).

#### 4.1.2 Consecutive Period Sequence Matrix (1 to 6 Periods)
The phonetic tokenizer implements longest-match greedy evaluation over the accumulated raw period sequence:
```
Greedy Precedence Order:
1. "...." -> \u{0965} (Double Dáñṛi '॥', consumes 4 bytes)
2. ".."   -> \u{0964} (Dáñṛi '।', consumes 2 bytes)
3. "."    -> Single period logic (consumes 1 byte)
```

| Consecutive Input | Tokenizer Parsing | Output String | Buffer Meaning / Lifecycle State |
| :---: | :--- | :--- | :--- |
| **`.`** | Single period rule | `.` | Pending period in preedit (or literal passthrough). |
| **`..`** | Matches `..` | **`।`** (`U+0964`) | Bengali Dáñṛi emitted immediately in preedit. |
| **`...`** | Matches `..` then `.` | **`।.`** | Bengali Dáñṛi followed by single pending period. |
| **`....`** | Matches `....` | **`॥`** (`U+0965`) | Bengali Double Dáñṛi emitted immediately. |
| **`.....`** | Matches `....` then `.` | **`॥.`** | Double Dáñṛi followed by single pending period. |
| **`......`** | Matches `....` then `..`| **`॥।`** | Double Dáñṛi followed by Bengali Dáñṛi. |

#### 4.1.3 Event Lifecycle & Backspace Deconstruction
- **Typing & Backspace:**
  Because `BornoEngine` re-evaluates the entire `raw_buffer` on each input event:
  - User types `..` $\to$ raw buffer `".."` tokenizes to `।`.
  - User presses `Backspace` $\to$ raw buffer becomes `"."` $\to$ tokenizes to single pending `.`.
  - User presses `Backspace` again $\to$ raw buffer empty $\to$ preedit cleared.
  - User types `....` $\to$ raw buffer `"...."` tokenizes to `॥`.
  - User presses `Backspace` $\to$ raw buffer `"..."` tokenizes to `।.`.
- **Escape / Reset:**
  - Pressing `Escape` or dispatching `EngineEvent::Reset` clears `raw_buffer` unconditionally without committing any punctuation.
- **Space & Enter / Commit:**
  - If preedit contains `।` (from `..`) or `॥` (from `....`), pressing `Space` commits the completed Dáñṛi followed by a space.
  - Pressing `Enter` or dispatching `EngineEvent::Commit` commits the completed Dáñṛi without adding trailing whitespace.

#### 4.1.4 Single-Period Auto-Dari Contract (`auto_convert_period_to_dari`)
- **Isolation:** `auto_convert_period_to_dari` controls **strictly single period (`.`) behavior**. It never alters the evaluation of `..` $\to$ `।` or `....` $\to$ `॥`.
- **Available Text Context:**
  The engine evaluates context from two sources:
  1. *Active Composition Buffer:* The token stream in `raw_buffer` preceding the period.
  2. *Committed Token History:* If the period is typed as a new composition immediately following a commit, the engine inspects the last committed character recorded in `EngineState`.
- **When `false` (Default):**
  - Single `.` remains literal ASCII `.` across all contexts and commits as `.`.
- **When `true`:**
  - When typed, `.` enters preedit buffer as pending punctuation.
  - **Numeric Safeguard:** If immediately preceded by ASCII digits (`'0'..='9'`) or Bengali digits (`'\u{09E6}'..='\u{09EF}'`) either in active composition or in the immediate commit history (e.g. `3.14`, `৩.১৪`), it is treated as a decimal point. It commits strictly as ASCII `.`.
  - **Domain / Extension Safeguard:** If followed by alphanumeric characters without intervening whitespace prior to commit (e.g. `borno.org`, `file.txt`), it commits as ASCII `.`.
  - **Sentence Termination:** If preceded by Bengali non-digit text and an explicit boundary event occurs:
    1. **Space Key:** Trailing `.` converts to `।` (`U+0964`), followed by space commit.
    2. **Enter / Commit Event:** Trailing `.` converts to `।` (`U+0964`) and commits.
    3. **Mode Switch Event:** If `auto_commit_on_mode_switch` is true, converts trailing `.` to `।` and commits.
  - **Cancellation:** `Escape` or `Reset` discards pending preedit without emitting `।`.
- **Fixed Layout Isolation:** National, Probhat, and Bijoy layouts retain their exact physical key tables. `auto_convert_period_to_dari` applies exclusively to phonetic mode.

### 4.2 Linguistic Ambiguity Generation & Ranking Contract

#### 4.2.1 Bounded Rules & Conditions
1. **Medial Vowel Alternation (`o` $\leftrightarrow$ `O`):**
   - **Condition:** Medial lowercase `o` immediately following a consonant cluster.
   - **Example (`tomake`):** Primary transliteration produces `তমাকে` (Slot 0). Ambiguity rule generates variant `tOmake`, which transliterates to `তোমাকে`. The engine queries `PrefixTrie::get_frequency("তোমাকে")`. Because `"তোমাকে"` exists in `lexicon.tsv` (rank 8644), it is admitted and placed in **Candidate Slot 1** (`ExactLexiconMatch`).
2. **Post-Reph Nasal Alternation (`rn` $\to$ `rN` / ণ-ত্ব বিধান):**
   - **Condition:** Sequence `rn` where `r` precedes `n` as a Reph.
   - **Generation & Gating:** Generates replacement of `rn` with `rN` (`borNomala`). Gated strictly by `PrefixTrie::get_frequency("বর্ণমালা")`. Once `"বর্ণমালা"` is compiled into the binary trie artifact, `get_frequency` returns its positive frequency and places it in **Candidate Slot 1** (`ExactLexiconMatch`).
3. **Negative Case Safeguards:**
   - **Prefix Boundaries & Foreign Loanwords:** Words such as `durniti` (`দুর্নীতি`, prefix boundary `dur-`) or foreign loanwords such as `kornel` (`কর্নেল`) have dental `ন`. When typed (`durniti`), the rule generates `durNiti` (`দুর্ণীতি`). The engine queries `PrefixTrie::get_frequency("দুর্ণীতি")`. Because `"দুর্ণীতি"` does not exist in the lexicon (`get_frequency` returns `None`), `"দুর্ণীতি"` is **strictly absent** from the candidate list. Slot 0 is preserved as `দুরনীতি`/`দুর্নীতি`, and legitimate completions or suggestions for `dur-` remain unaffected.
   - For `kornel`, the rule generates `korNel` (`কৰ্ণেল`). Gated by lexicon, `"কৰ্ণেল"` is strictly absent from candidates, preserving Slot 0 (`কর্নেল`).
   - **Unmatched Strings:** Arbitrary strings containing `rn` (e.g. `karnival`) produce no ambiguity candidates if the transformed form is absent from the lexicon.

#### 4.2.2 Ranking, Deduplication & Invariants
- **Budget:** `MAX_AMBIGUITY_VARIANTS = 4`.
- **Order of Operations:**
  1. Direct transliteration $\to$ Candidate Slot 0 (`PrimaryTransliteration`).
  2. Ambiguity variant generation $\to$ Filtered through `PrefixTrie::get_frequency`.
  3. Sort validated ambiguity matches by frequency descending (lexicographic tie-break).
  4. Deduplication via `push_candidate`: If an ambiguity match equals Candidate Slot 0, it is discarded, and the next distinct match is promoted.
  5. Validated distinct ambiguity matches occupy Candidate Slot 1+ (`ExactLexiconMatch`), bounded by `max_dictionary_suggestions`.
  6. Fill remaining display budget (`candidate_display_limit`) with prefix completions and spelling corrections.
- **Dictionary Disabled Isolation:** If `enable_dictionary_assistance` is `false`, ambiguity generation is bypassed entirely; only Candidate Slot 0 is returned.

#### 4.3.2 Whitelist-Based Schema Migration & Invariant Validation
- **Exact Whitelist Comparison (No Lexicographic Checks):**
  Instead of fragile lexicographic string comparison (`version < "1.2.0"`), `BornoConfig::from_json_str` uses an **exact string whitelist**:
  ```rust
  match version_str {
      "1.0.0" => migrate_v1_0_to_v1_2(&mut raw_val)?,
      "1.1.0" => migrate_v1_1_to_v1_2(&mut raw_val)?,
      "1.2.0" => (), // Target schema
      other => return Err(ConfigError::UnsupportedSchemaVersion(other.to_string())),
  }
  ```
  Unsupported future schema versions (`"1.3.0"`, `"2.0.0"`, `"1.2.0-beta"`) or arbitrary strings are rejected immediately, preserving stored disk files byte-for-byte untouched.
- **Independent Budgets Invariant Validation:**
  Inspection of `ranker.rs` confirms that `candidate_display_limit` (UI presentation capacity, `1..=9`) and `max_dictionary_suggestions` (dictionary query quota, `1..=5`) represent independent budgets. The ranker gracefully truncates candidate output to `display_limit`. Validation enforces:
  - `candidate_display_limit` in `1..=9`.
  - `max_dictionary_suggestions` in `1..=5`.
  - `candidate_font_size` in `10..=24` (points).
  - Valid enum variants.
  No artificial cross-field constraint is imposed, ensuring every valid slider position in the UI serializes to a valid configuration.

### 4.4 C-ABI Configuration Delivery Contract

#### 4.4.1 FFI Declaration in `include/bornomala.h` and `src/ffi.rs`
```c

#define BORNO_ERR_INVALID_CONFIG     -5

    BornoEngineHandle* handle,
    const char* json_utf8

```

#### 4.4.2 Behavioral Specifications & Composition Preservation
- **Ownership & Lifetime:** Caller retains ownership of `json_utf8`. The Rust core reads the string during the call and retains no pointers or references after return.
- **Parsing & Validation Location:** All parsing, migration, and validation occur inside the Rust core (`BornoConfig::from_json_str`).
- **Failure Invariant:** If configuration fails, the engine instance remains **completely unmodified** in its previous valid state.
- **Active Composition Invariant (Preserved Across Configuration):**
  - If the engine has active composition in `raw_buffer`:
    - `state.preedit`, `state.raw_buffer`, and `state.is_composing` are **preserved completely intact**.
    - Preedit is **never committed or cancelled** merely because configuration was updated.
    - `set_preferred_fixed_layout` updates `engine.preferred_fixed_layout()` for future fixed mode switches, matching the existing architectural contract in [`tests/engine_config_tests.rs:L83-L104`](../crates/bornomala-core/tests/engine_config_tests.rs#L83-L104). The active fixed layout table remains unchanged until the next mode switch.
    - Slicing limits (`candidate_display_limit`) and punctuation rules (`auto_convert_period_to_dari`) apply to subsequent keystrokes and candidate presentation.

### 4.5 Transactional Persistence, Import, Export & Recovery

#### 4.5.1 Ordinary Settings Persistence (Tauri Backend)
- **Tauri IPC Command:**
  ```rust
  #[tauri::command]
  pub fn save_config(config: BornoConfig) -> Result<(), String>
  ```
  - Dispatched immediately by the frontend when settings change (debounced for sliders).
  - Validates invariants, creates backup `config.json.bak`, writes atomically, applies to runtime backend engine, and returns `Ok(())`.

#### 4.5.2 Authoritative Import/Export Architecture
- **Canonical Owner:** The canonical configuration is owned by the **Tauri backend / filesystem** (`%APPDATA%\com.bornomala.desktop\config.json` on Windows, `~/.config/...` on Linux).
- **Export Flow:**
  1. Frontend invokes Tauri command `export_config()`.
  2. Backend reads active validated configuration from `config_store`, serializes with pretty printing, and returns the JSON string.
  3. Frontend triggers an HTML5 Blob download (`bornomala-config-v1.2.0.json`).
- **Import Flow (Two-Phase Transaction with Safe Rollback):**
  1. Frontend reads raw file text via HTML5 `FileReader` and dispatches `import_config(json_str)`.
  2. **Stage & Validate (In-Memory):** Parse JSON, verify whitelist version, migrate legacy fields, and validate invariants. If validation fails $\to$ abort (no disk or engine change).
  3. **Stage Engine Check:** Test-apply candidate configuration to the engine in memory.
  4. **Disk Commit:**
     - Copy `config.json` to `config.json.bak` (copying preserves backup for future recovery).
     - Write candidate JSON to `config.json.tmp.<pid>_<timestamp>`.
     - Flush and sync bytes to disk (`file.sync_all()`).
     - Atomic rename `config.json.tmp` over `config.json`. On Windows, retry up to 3 times (50ms interval) on transient file locks.
  5. **Runtime Application & Rollback:**
     - Apply candidate configuration to active backend engine.
     - If runtime application fails: copy `config.json.bak` back over `config.json`, restore previous engine configuration, and return `Err(RuntimeApplicationFailed)`.
     - If disk rollback itself fails: mark `PersistenceStatus::ReadOnlyCorruptedRollbackFailed`, log diagnostic alert, and return `Err(RollbackFailed)`. Never falsely report success.
  6. Return `Ok(BornoConfig)` to frontend.

#### 4.5.3 Factory Reset Protocol
1. User clicks "Restore Defaults" and confirms in modal dialog.
2. Tauri command `reset_config_to_defaults()` executes transactional commit:
   - Backs up current `config.json` to `config.json.bak`.
   - Writes `BornoConfig::default()` atomically.
   - Applies defaults to active engine.
   - Returns default config to frontend.

#### 4.5.4 Startup Recovery Protocol
- **Missing File:** Write `BornoConfig::default()` atomically.
- **Malformed JSON:** Back up corrupt file to `config.json.corrupt.<timestamp>`, write fresh default configuration, and log diagnostic warning.
- **Unsupported Schema Version (`> 1.2.0`):** Preserve file byte-for-byte untouched; return in-memory defaults with `PersistenceStatus::LockedUnsupportedVersion`.

### 4.6 Native Configuration Reload & Cross-Process Synchronization

#### 4.6.1 Process Boundaries & Discovery Mechanism
- **Tauri Sandbox (`bornomala-desktop.exe`):** Writes canonical `%APPDATA%\com.bornomala.desktop\config.json`.
- **Windows TSF (`borno-tsf.dll`):** Loaded into target applications (`notepad.exe`, `word.exe`).
- **Linux Fcitx 5 (`bornomala.so`):** Runs inside the `fcitx5` daemon process.
- **Multi-Attribute Change Detection:**
  Native adapters track:
  1. `LastWriteTime` (file modification timestamp).
  2. `FileSize` (byte count).
  3. Content revision / hash.
  Checked on context activation (`OnSetFocus` in TSF, `activate()` in Fcitx 5) and hotkey toggle (`VK_F12`/`VK_F4`), yielding perceived synchronization delay under 5ms.
- **Failure Resilience & Retry:**
  - If read fails due to a transient file lock: retry on next keystroke/focus event (100ms interval).
  - If parsing or validation fails (e.g. malformed manual edits): **retain last known valid configuration** in native memory, log warning, and do not crash or corrupt the active engine.
  - Active composition is preserved completely during native reload.
