## 1. Milestone Purpose and Architectural Value

- **Purpose:** Define and enforce the formal behavioral contract (normalized events, persistent state, ephemeral output effects, and composition lifecycle) that every platform adapter (Windows TSF, Linux Fcitx, macOS InputMethodKit) and the desktop sandbox will consume.
- **Architectural Rationale:** M0 established the runnable desktop sandbox and decoupled Rust core; M0.1 validated the C-ABI FFI boundary and confirmed Windows TSF feasibility. Before introducing expansive phonetic rule tables (M3) or fixed keyboard layout maps (M4), the engine must establish an unambiguous, version-controlled contract. This ensures:
  1. Platform adapters remain thin translation layers that never invent their own composition, cursor, or candidate selection rules.
  2. Persistent engine state is cleanly separated from step-level output effects, completely eliminating stale committed text bugs.
  3. Memory ownership across the C-ABI and serialization across Tauri IPC remain strictly consistent, safe, and leak-free.
  4. The desktop sandbox serves as a high-fidelity testbed where every event, state transition, and output effect can be interactively and visually inspected.

## 3. Scope and Explicit Non-Goals

### In-Scope

1. **Separation of Persistent State from Output Effects (Correction 1):**
   - **Persistent `EngineState`:** Retains only ongoing composition properties:
     ```rust
     pub struct EngineState {
         pub preedit: String,
         pub raw_buffer: String,
         pub cursor_pos: usize,
         pub candidates: Vec<String>,
         pub selected_candidate_index: Option<usize>,
         pub is_composing: bool,
         pub mode: InputMode,
         pub status: EngineStatus,
     }
     ```
     `committed_text` is explicitly removed from `EngineState`, preventing stale text from lingering across subsequent events.
   - **Ephemeral `ProcessResult` (Output Effect):** Produced by event processing:
     ```rust
     pub struct ProcessResult {
         pub state: EngineState,
         pub committed_text: Option<String>,
         pub cancelled: bool,
         pub handled: bool,
     }
     ```
     - `committed_text`: `Some(String)` only on the specific event step that commits text (e.g. `Commit`, `SelectCandidate`, Space/Enter, or typing in passthrough mode); `None` on all other steps.
     - `cancelled`: `true` only when the active composition was explicitly aborted/cancelled (e.g. `Cancel` / Esc); `false` otherwise.
     - `handled`: `true` if the engine consumed the event; `false` if unhandled (signaling the platform adapter to allow host OS default processing).

2. **Composition & Cursor Semantics (Correction 2):**
   - **Relationship between `raw_buffer` and `preedit`:**
     - `raw_buffer`: Stores uncommitted Latin keystrokes driving the current composition (e.g., `"k"`, `"ka"`).
     - `preedit`: Active provisional Bangla Unicode representation generated from `raw_buffer` (e.g., `"ক"`, `"কা"`).
     - In M1, transliteration is deterministic via `translit::transliterate`.
   - **Cursor Semantics & Indexing Unit:**
     - `cursor_pos: usize` measures the cursor position within the provisional `preedit` string.
     - Indexing unit: strictly measured in **Unicode scalar values (codepoints)**, NOT byte offsets and NOT UTF-16 code units.
     - Bounds invariant: strictly clamped to `0 <= cursor_pos <= preedit.chars().count()`.
     - When appending characters, `cursor_pos` advances to the end of `preedit`.
     - `SetCursor(pos)` clamps `pos` to `min(pos, preedit.chars().count())`.
     - `MoveCursorLeft`: decrements `cursor_pos` by 1 if `> 0`; clamps at 0.
     - `MoveCursorRight`: increments `cursor_pos` by 1 if `< count`; clamps at `preedit.chars().count()`.
   - **Backspace & Delete Semantics:**
     - While `is_composing == true`:
       - `Backspace` at `cursor_pos > 0`: removes the codepoint preceding `cursor_pos`, updates `raw_buffer`, recomposes `preedit`, decrements `cursor_pos`, and updates candidates. If the buffer becomes empty, composition ends (`is_composing = false`).
       - `Backspace` at `cursor_pos == 0`: no-op within composition; returns `handled = false`.
       - `Delete` at `cursor_pos < preedit.chars().count()`: removes the codepoint following `cursor_pos`, updates `raw_buffer`, recomposes `preedit`, maintains `cursor_pos` (clamped to new length), and updates candidates.
       - `Delete` at `cursor_pos == preedit.chars().count()`: no-op within composition; returns `handled = false`.
   - **Composition Boundary vs Host Document Editing:**
     - The engine's cursor and deletion operations apply exclusively to the active composition buffer.
     - When `is_composing == false` (idle), keystrokes like `Backspace`, `Delete`, and arrow keys return `handled = false`, signaling the platform adapter or host document to handle host text editing.
   - **Linguistic Boundary Disclaimer:**
     - M1 operates strictly on Unicode codepoints. Complex Bangla grapheme cluster normalization (preserving vowel signs, hasanta sequences, and multi-codepoint conjuncts like `ক্ষ`) is explicitly deferred to **M2 (Bangla Unicode & Phonetic Core)**. M1 makes no claim of full linguistic Unicode editing correctness.

3. **Candidate Navigation & Selection Contract (Correction 3):**
   - **Candidate Highlight vs Selection Commit:**
     - `HighlightCandidate(usize)`: Sets `selected_candidate_index = Some(index)` (validated against `candidates.len()`). Does NOT commit text; composition remains active (`is_composing = true`).
     - `NextCandidate`: Increments `selected_candidate_index` with wrap-around (`last -> 0`). If no candidate was highlighted, highlights index 0. Does NOT commit text.
     - `PrevCandidate`: Decrements `selected_candidate_index` with wrap-around (`0 -> last`). If no candidate was highlighted, highlights the last index. Does NOT commit text.
     - `SelectCandidate(usize)`: Chooses candidate at `index` and **commits it immediately**. Emits `committed_text = Some(candidates[index])`, clears preedit/raw_buffer/candidates, sets `is_composing = false`, and returns engine to `Idle`.
     - `Commit`: Commits the currently highlighted candidate (`selected_candidate_index`). If no candidate is highlighted, falls back to candidate `0`; if candidates list is empty, falls back to committing active `preedit`; if `preedit` is empty, emits `committed_text = None`.
   - **Boundary & Error Behavior:**
     - Empty candidates list: `NextCandidate` and `PrevCandidate` are safe no-ops (`selected_candidate_index = None`); `SelectCandidate` returns `handled = false` with unchanged state.
     - Out-of-bounds index (`index >= candidates.len()`): `SelectCandidate` and `HighlightCandidate` return `handled = false` (or `BORNO_ERR_INVALID_ARGUMENT` in C-ABI); state is NOT modified.
   - **Sandbox UI Interaction Parity:**
     - Mouse click on a candidate tile dispatches `SelectCandidate(i)` (immediate commit).
     - Numeric keys `1`–`9` dispatch `SelectCandidate(key - 1)` (immediate commit).
     - Up/Down arrows and Tab dispatch `NextCandidate` / `PrevCandidate` (highlight only).
     - Enter and Space dispatch `Commit` (commits highlighted candidate).

4. **Normalized Event Model & Event Boundary (Correction 4):**
   - **OS Event Translation:**
     - Platform adapters (TSF on Windows, IBus on Linux, DOM on Web/Tauri) translate physical keys, virtual keycodes (`VK_SPACE`, `VK_RETURN`, `VK_BACK`), and modifiers into normalized `EngineEvent` instances.
     - Core engine contains NO OS-specific or UI-specific types.
   - **Normalized Events (`EngineEvent`):**
     ```rust
     pub enum EngineEvent {
         InputChar(char),
         InputString(String),
         Backspace,
         Delete,
         Commit,
         Cancel,
         Reset,
         NextCandidate,
         PrevCandidate,
         HighlightCandidate(usize),
         SelectCandidate(usize),
         SetCursor(usize),
         MoveCursorLeft,
         MoveCursorRight,
         SwitchMode(InputMode),
     }
     ```
   - **InputString Semantics:**
     - In `Phonetic` mode: appends string to `raw_buffer`, recomposes `preedit`, updates candidate list, sets `cursor_pos = preedit.chars().count()`.
     - In `EnglishPassthrough` mode: immediately emits `committed_text = Some(s)` with `is_composing = false`.
   - **Reset vs Cancel Semantics:**
     - `Cancel`: User-initiated abort (e.g. `Esc`). Clears active composition and emits `cancelled = true, committed_text = None, handled = true`.
     - `Reset`: Host-initiated lifecycle reset (e.g. focus loss, window destruction). Silently resets all state to idle without emitting cancellation effects (`cancelled = false, committed_text = None, handled = true`).
   - **Mode Switching Semantics:**
     - `SwitchMode(InputMode)` (`Phonetic` vs `EnglishPassthrough`):
       - If `is_composing == true`: auto-commits the active `preedit` string (`committed_text = Some(preedit)`), resets composition buffers, sets `mode`, updates `status.active_mode`, and returns to idle.
       - If `is_composing == false`: switches `mode` and updates `status.active_mode` immediately.
   - **Unhandled / Invalid Operations:**
     - Operations that cannot be performed (e.g. `Backspace` when idle, `MoveCursorLeft` at 0, out-of-bounds selection) preserve all state invariants and return `handled = false, committed_text = None`.

5. **C-ABI Boundary Protection (Correction 5):**
   - **Zero Rust-Specific Types Exposed:**
     - No Rust `String`, `Vec`, `Option`, or unadorned Rust enums cross the `extern "C"` boundary.
     - Structs in `crates/borno-core/include/borno.h` and `crates/borno-core/src/ffi.rs`:
       - `BornoStatusC`: `char* name`, `char* version`, `char* active_mode`, `bool ready`.
       - `BornoStateC`: `char* preedit`, `char* raw_buffer`, `size_t cursor_pos`, `size_t candidates_count`, `char** candidates`, `int32_t selected_candidate_index` (-1 for none), `bool is_composing`, `int32_t mode`.
       - `BornoProcessResultC`: `BornoStateC state`, `char* committed_text` (or NULL), `bool cancelled`, `bool handled`.
       - `BornoEventC`: Tagged union/struct with `int32_t event_type` and appropriate scalar/pointer payloads.
   - **Memory Ownership & Buffer Handling:**
     - Pointers allocated by the Rust allocator must be freed by Rust helpers: `borno_string_free(char*)`, `borno_state_free_members(BornoStateC*)`, `borno_process_result_free_members(BornoProcessResultC*)`.
     - Input string pointers (`*const c_char`) are borrowed; caller retains ownership.
     - All C-ABI functions wrapped in `std::panic::catch_unwind` to prevent unwinding across FFI.
     - Error reporting: explicit status codes (`BORNO_OK`, `BORNO_ERR_NULL_PTR`, `BORNO_ERR_INVALID_UTF8`, `BORNO_ERR_PANIC`, `BORNO_ERR_INVALID_ARGUMENT`).
   - **FFI & IPC Consistency:**
     - Both FFI and Tauri IPC express the exact same engine contract: normalized event in -> persistent state + output effects out.

6. **Single-Pathway Authoritative IPC (Correction 6):**
   - **Reuse Existing IPC Pathway:**
     - Update Tauri command `send_engine_event(event: EngineEvent) -> Result<ProcessResult, String>` to return `ProcessResult`.
     - Do NOT add redundant commands for individual events (`commit_engine`, `cancel_engine`, `select_candidate`, etc.).
     - `reset_engine` is retained or redirected as a convenience wrapper around `EngineEvent::Reset`.
   - **Authoritative Core:**
     - All state transitions, candidate rankings, cursor clamping, and text commitments happen exclusively in the Rust core.
     - React acts strictly as a presentation and event-capture layer; no engine logic is duplicated in TypeScript.

7. **Comprehensive Contract Verification Suite (Correction 7):**
   - Automated tests in `crates/borno-core/tests/contract_tests.rs` covering:
     - State invariants (buffer lengths, cursor bounds, candidate indexing, effect cleanup).
     - Full composition lifecycle (`Idle` -> `InputChar` -> `Commit`/`Cancel` -> `Idle`).
     - In-composition cursor movements, clamping, and interior backspace/delete.
     - Candidate highlight, wrap-around navigation, direct selection commit, and invalid index rejection.
     - Mode switching during composition with auto-commit.
     - C-ABI FFI parity and memory safety.
     - Regression testing for all 11 M0 unit tests and 5 M0.1 FFI tests.

8. **Enhanced Desktop Sandbox Contract UI (Correction 8):**
   - Visible in-preedit cursor marker reflecting `cursor_pos`.
   - Interactive candidate tiles with highlight state and click-to-select.
   - Full keyboard bindings: `1-9` select, `ArrowUp`/`ArrowDown` highlight, `Esc` cancel, `Enter`/`Space` commit.
   - Mode switcher toggle (`Phonetic` vs `English Passthrough`).
   - Event Inspector displaying normalized events, state diffs, committed effects, and round-trip IPC latency (ms).

### Explicit Non-Goals
- Full phonetic transliteration rule table, Avro corpus, or dictionary scoring (deferred to M3).
- Fixed keyboard layouts (Bijoy, National, Probhat) (deferred to M4).
- System-wide Windows IME TSF hooks or elevated installation (deferred to M7/M12).
- Trie-based word completion or spelling assistance (deferred to M6).
- Full complex Bangla grapheme cluster / conjunct boundary normalization (deferred to M2).

## 6. Stop Conditions & Risk Management

- **Regression Stop:** If refactoring `EngineState` or `EngineEvent` causes any of the 11 baseline unit tests or 5 FFI tests to fail, halt immediately and resolve before proceeding with frontend changes.
- **Scope Boundary:** Do not implement full Avro dictionary lookups, phonetic rule tables, or system-wide TSF hooks in M1; candidate lists are deterministic fixtures.
- **Observability vs Optimization:** The Event Inspector measures round-trip IPC and engine latency for observability and contract debugging; formal benchmark optimization belongs to M11.
- **Execution Gate:** M1 is complete only when all 9 acceptance criteria are verified and the completion report is approved. Do not proceed to M2 until M1 is approved.
