## 1. Milestone Purpose and Architectural Role

- **Purpose:** Establish a rigorous, standards-compliant Unicode foundation for the Bangla script in the shared Rust core (`crates/borno-core`), cleanly separating Unicode normalization, character classification, composition policy, grapheme cluster segmentation, and text rendering/shaping.
- **Architectural Rationale:** Text corruption in Indic input methods typically stems from conflating Unicode standards with application typing heuristics or trying to perform font glyph shaping inside the input engine. M2 resolves this by:
  1. **Enforcing Standard Normalization (NFC):** Ensuring canonical equivalence according to Unicode Standard Annex #15 (UAX #15), eliminating data discrepancies across search engines, operating systems, and databases.
  2. **Decoupling Composition from Font Shaping:** The core engine produces standard, canonically ordered Unicode codepoint sequences. Complex conjuncts (যুক্তবর্ণ such as `ক্ষ` = `ক` + `্` + `ষ`) and vowel signs are preserved as valid Unicode codepoint streams; visual ligature formation is strictly delegated to the host platform's OpenType font shaper (DirectWrite, HarfBuzz, CoreText).
  3. **Distinguishing Standard vs. Borno-Specific Rules:** Standard canonical equivalence (e.g. two-part vowel composition `ে + া` ➔ `ো`, canonical nukta decomposition `ড়` ➔ `ড + ়`) is handled strictly via authoritative Unicode algorithms (UAX #15). Application-specific rules (such as direct Khanda-Ta `ৎ` input generation, joiner preservation by default, Reph composition, or phonetic vowel replacement) are explicitly documented and tested as **Input Composition Policy**, never mislabeled as standard NFC.
  4. **Conservative In-Composition Sanitization:** Live input sanitization applies exclusively to provisional composition buffers. Committed user text, punctuation, mixed English/Bangla text, and intentional joiners (ZWJ/ZWNJ) are strictly preserved without silent modification.
  5. **Layered Golden Verification:** Replacing arbitrary test counts with a layered test matrix verifying standard normalization, code point classification, grapheme segmentation, composition edge cases, and mixed-script preservation.

## 3. Architectural Separation of Concerns

To avoid the architectural traps common in Indic input systems, M2 strictly separates five distinct layers:

```
┌────────────────────────────────────────────────────────────────────────┐
│ 1. Unicode Normalization (NFC / UAX #15)                              │
│    Canonical equivalence: decomposed two-part vowels & nuktas         │
├────────────────────────────────────────────────────────────────────────┤
│ 2. Bangla Character Classification (Unicode Character Database)        │
│    Code point properties: Vowel, Consonant, Kar, Virama, Nukta, etc.   │
├────────────────────────────────────────────────────────────────────────┤
│ 3. Composition Policy (Borno Engine Input State Machine)               │
│    Input sequences: Reph, Ya-phala, Khanda-Ta, vowel-kar placement     │
├────────────────────────────────────────────────────────────────────────┤
│ 4. Grapheme Cluster Segmentation (UAX #29 Extended Graphemes)          │
│    Cursor navigation boundaries and backspace deletion units          │
├────────────────────────────────────────────────────────────────────────┤
│ 5. Text Rendering & OpenType Shaping (External: OS DirectWrite/HarfBuzz)│
│    Ligatures (ক্ষ, জ্ঞ), vowel placement, font glyph rendering         │
└────────────────────────────────────────────────────────────────────────┘
```

1. **Unicode Normalization:** Standard canonical equivalence defined by the Unicode Consortium. Converts canonically equivalent sequences to standard NFC.
2. **Character Classification:** Code point membership in the Bengali Unicode block (`U+0980`–`U+09FF`) and associated Unicode general categories.
3. **Composition Policy:** Application-specific heuristics for translating user keystrokes into provisional Bangla sequences (e.g. typing a vowel after a consonant produces a vowel sign; typing `r` + hasanta + consonant produces Reph).
4. **Grapheme Segmentation:** Grouping codepoint sequences into user-perceived characters for cursor movement and backspace.
5. **Rendering & Shaping:** Purely external. Borno never outputs font glyph indices or private-use codepoints; it outputs standard Unicode text for the OS font engine to shape.

2. **Standard-Defined Unicode Normalization (NFC Policy):**
   - Delegate canonical decomposition, canonical combining class sorting, and canonical composition strictly to the established `unicode-normalization` crate (UAX #15). Do NOT implement a custom canonical reordering algorithm.
   - **Standard Canonical Compositions (UAX #15):**
     - Two-part vowel signs compose canonically in standard NFC (tested separately from mixed-script strings):
       - *Isolated dependent vowel signs:*
         - `\u{09C7}\u{09BE}` (`ে` + `া`) ≡ `\u{09CB}` (`ো` BENGALI VOWEL SIGN O)
         - `\u{09C7}\u{09D7}` (`ে` + `ৗ`) ≡ `\u{09CC}` (`ৌ` BENGALI VOWEL SIGN AU)
       - *Syllable vowel signs with base consonant:*
         - `\u{0995}\u{09C7}\u{09BE}` (`ক` + `ে` + `া`) ≡ `\u{0995}\u{09CB}` (`কো`)
         - `\u{0995}\u{09C7}\u{09D7}` (`ক` + `ে` + `ৗ`) ≡ `\u{0995}\u{09CC}` (`কৌ`)
   - **Authoritative Unicode Standard Fact & Borno Policy — Nukta Decomposition in Committed Text:**
     - In the Unicode Standard (UAX #15, `CompositionExclusions.txt`), `ড়` (`U+09DC`), `ঢ়` (`U+09DD`), and `য়` (`U+09DF`) are designated as **Full Composition Exclusions**.
     - Standard NFC does **NOT** recompose `ড + ়` into `ড়`; the canonical NFC representation in Unicode is the decomposed sequence `Consonant + Nukta` (`ড` [09A1] + `়` [09BC], `ঢ` [09A2] + `়` [09BC], `য` [09AF] + `়` [09BC]).
     - Precomposed `U+09DC`, `U+09DD`, and `U+09DF` canonically decompose under standard NFC into these two-character sequences.
     - **Borno Committed Text Normalization Policy:** Borno strictly enforces standard NFC normalization on all committed text emitted via `ProcessResult.committed_text`. Consequently, strict NFC normalization of committed text decomposes `ড়`, `ঢ়`, and `য়` into their canonical decomposed sequences (`ড + ়`, `ঢ + ়`, `য + ়`), ensuring 100% strict adherence to Unicode standard canonical equivalence across all downstream storage, text engines, and search indexes.
     - OpenType font shapers (DirectWrite, HarfBuzz, CoreText) render these canonical decomposed sequences identically to the atomic glyphs across all modern Bangla fonts.
     - Test assertions reflect this invariant directly: `normalize_nfc("বাড়ি")` yields `"বা\u{09A1}\u{09BC}ি"`. During active typing, if layout tables emit atomic nukta codepoints into preedit, passing preedit through `normalize_nfc` canonically decomposes them to the standard two-codepoint sequences.
   - **Strict NFC Boundary Definition:**
     - **What Borno Normalizes:** Text actively composed or transformed by Borno—specifically the live provisional `preedit` buffer and emitted `committed_text`.
     - **What Borno Preserves Unmodified:** Existing document text, host application content, and text outside active composition. Borno is an input engine, not a global document sanitizer, and will NEVER retroactively rewrite unmanaged host text.
   - **Partitioned Normalization & Preservation Invariants:**
     - **Pure ASCII / Punctuation Preservation:** Strings composed purely of ASCII characters (`[a-zA-Z0-9.,!? ]`) are guaranteed byte-identical: `NFC(s) == s`.
     - **Already-Normalized Idempotency:** Any valid string already in NFC (Bangla, English, or mixed) satisfies `NFC(s) == s` and `NFC(NFC(s)) == NFC(s)`.
     - **Canonical Normalization Verification:** Decomposed two-part vowels (`ে + া`, `ে + ৗ`) compose deterministically to `ো` and `ৌ`. Nukta sequences (`ড + ়`) remain in their standard decomposed NFC form (`ড + ়`), and atomic nukta characters (`ড়`, `ঢ়`, `য়`) decompose to `ড + ়`, `ঢ + ়`, `য + ়`.
     - **Mixed-Script Normalization:** When mixed-script text contains decomposable sequences, NFC normalizes the decomposable characters while leaving surrounding ASCII Latin characters and punctuation strictly byte-identical:
       - *Decomposable mixed-script test vector:* `"Node.js \u{0995}\u{09C7}\u{09BE}ড"` (`"Node.js "` + `ক` + `ে` + `া` + `ড`) normalizes under NFC to `"Node.js কোড"` (`"Node.js "` + `ক` + `ো` + `ড`), where the decomposable vowel sequence in the Bangla syllable composes canonically to `কোড` and the ASCII substring `"Node.js "` remains strictly byte-identical.
       - *Already-normalized mixed-script test vector:* `"Version 2.0: \u{09AC}\u{09BE}\u{0982}\u{09B2}\u{09BE}"` (`"Version 2.0: বাংলা"`) remains strictly byte-identical (`NFC(s) == s`).

3. **Borno Composition Policy (Application Rules vs. Standards):**
   - Explicitly separate application-level typing heuristics from standard Unicode NFC:
     - **Khanda-Ta (`ৎ` U+09CE) & Joiner Preservation Policy:**
       - **Modern Atomic Khanda-Ta:** In Unicode (since 4.0), Khanda-Ta is an independent atomic character (`U+09CE`) with NO canonical decomposition. Borno maps explicit input keys/transliteration rules directly to atomic `U+09CE`.
       - **Joiners Preserved by Default:** Zero-Width Joiner (ZWJ `U+200D`) and Zero-Width Non-Joiner (ZWNJ `U+200C`) are strictly preserved by default across normalization and standard in-composition sanitization. Standard typing and sanitization NEVER mutate or strip joiners.
       - **Narrowly Scoped Legacy Conversion Helper:** The legacy sequence `ত` (`U+09A4`) + `্` (`U+09CD`) + `ZWJ` (`U+200D`) was historically used before `U+09CE` was encoded. If legacy conversion is supported, it is decoupled from the main input pipeline and implemented as an explicit, narrowly scoped compatibility helper function (`convert_legacy_khanda_ta(s: &str) -> String`) with its own dedicated tests. It is NOT invoked automatically during normal typing or ambient text sanitization, preventing unintended mutations of user-entered joiners.
     - **Nukta-Derived Characters (`ড়`, `ঢ়`, `য়`):** Keyboard layouts or transliteration rules may accept user input targeting these characters. However, because committed text is strictly NFC-normalized, the engine's final output will always emit their canonical decomposed sequences (`ড + ়`, `ঢ + ়`, `য + ়`), conforming to Unicode UAX #15. Test suites verify that both atomic inputs and decomposed inputs normalize to the canonical decomposed sequences.
     - **Format Control Characters (Tested Independently):**
       - **ZWNJ (`U+200C`, Zero-Width Non-Joiner):** Expresses a Unicode non-joining request / ligature suppression intent (e.g. `ক` + `্` + `ZWNJ` + `ক`), signaling to the text shaping engine not to form a conjunct ligature across the syllable boundary. The visual manifestation (whether rendered with an explicit visible hasanta glyph or an isolated consonant shape) is determined entirely by the host OpenType font rules and text shaper (HarfBuzz, DirectWrite, CoreText), not by the input engine.
       - **ZWJ (`U+200D`, Zero-Width Joiner):** Expresses a Unicode joining request, used in specific Indic script contexts to request half-forms or ligated presentation.
       - *Note on Visual Rendering:* Actual visual presentation depends entirely on the host OpenType font and shaper (DirectWrite/HarfBuzz); the engine's contract guarantees the output of exact, valid Unicode control sequences without making visual glyph guarantees.
     - **Conjunct Sequences:** Encoded strictly as `Consonant + Virama (্) + Consonant` (e.g. `ক + ্ + ষ` = `ক্ষ`). Zero custom PUA codes or glyph substitutions.
     - **Reph Formation:** Encoded as `র` (`U+09B0`) + `্` (`U+09CD`) + `Consonant`.
     - **Phala Formations:** Ya-phala (`Consonant + ্ + য`), Ra-phala (`Consonant + ্ + র`), Ba-phala (`Consonant + ্ + ব`).
     - **Vowel Kar Placement:** In abugida typing, a vowel entered after a consonant/conjunct attaches as a dependent vowel sign (Kar), while a vowel entered at word start attaches as an independent vowel.

4. **Scoped In-Composition Sanitization:**
   - **Strict Context Boundary:** Sanitization is an application input policy applied ONLY during active composition states (`is_composing == true`) to the provisional buffer (`raw_buffer` / `preedit`). It is NEVER applied to committed document text or arbitrary external strings.
   - **Explicit Transformation Policies:**
     - **Vowel-Sign Replacement:** Only triggered when the user enters a dependent vowel sign immediately following an existing dependent vowel sign on the active syllable during live typing. The newly typed vowel replaces the preceding one in the provisional preedit (matching typing correction intent). Arbitrary strings or non-typing contexts are not modified.
     - **Hasanta Collapsing:** Typing two consecutive hasantas (`্ + ্`) in active composition collapses to a single `্`. Hasantas followed by joiners (`্ + ZWNJ` or `্ + ZWJ`) are strictly preserved.
     - **No Artificial Consonant Injection:** Do NOT inject artificial consonants (e.g. do NOT insert `অ` under orphan vowel signs).
     - **Preservation Invariant:** Intentional ZWJ/ZWNJ controls, mixed-script Latin text, whitespace, and punctuation are strictly preserved without modification.

5. **Cursor and Editing Policy (Contract-Aligned with Explicit Limitations):**
   - **M1 Contract Compatibility:**
     - `EngineState.cursor_pos` is maintained strictly as a 0-based Unicode scalar value (codepoint) index (`0..=preedit.chars().count()`).
   - **In-Composition Scalar Editing Policy:**
     - **Backspace:** Deletes the single Unicode scalar immediately preceding `cursor_pos` (or in phonetic mode, pops the corresponding input token in `raw_buffer` and re-evaluates `preedit`).
       - *Example:* On `কা` (cursor at pos 2), Backspace deletes `া`, leaving `ক` (cursor at pos 1).
       - *Example:* On `ক্ষ` (`ক` + `্` + `ষ`, cursor at pos 3), Backspace deletes `ষ`, leaving `ক্` (`ক` + `্`, cursor at pos 2).
       - *Example:* On `ক্` (cursor at pos 2), Backspace deletes `্`, leaving `ক` (cursor at pos 1).
     - **Delete:** Deletes the single Unicode scalar immediately following `cursor_pos`.
     - **Cursor Movement (`MoveCursorLeft` / `MoveCursorRight`):** Steps by single Unicode scalars (`cursor_pos ± 1`), clamped to valid bounds.
   - **Explicit Editing Limitations (Preserved for M2):**
     - Inside active preedit, Backspace, Delete, and cursor movement intentionally operate on individual Unicode scalars, which may be inside a visible conjunct or user-perceived grapheme.
     - This is an **intentional M2 composition editing policy**, chosen to provide granular typing correction and preserve 100% backward compatibility with M1's contract; it is NOT a claim that intra-preedit editing is grapheme-cluster-atomic.
     - UAX #29 extended grapheme cluster segmentation (via `unicode-segmentation`) is exposed as engine utilities (`unicode::grapheme_count`, `unicode::grapheme_indices`) for host selection, whole-syllable snapping, and future milestone needs; it does not govern intra-composition caret stepping in M2.
     - Any future transition to grapheme-cluster-based cursor movement or document-level text-store editing requires a separately defined contract and regression suite (deferred to M7).
   - **Deterministic Cursor-Affinity Procedure (`map_cursor_after_normalization`):**
     - **Signature:** `pub fn map_cursor_after_normalization(original: &str, original_cursor: usize, normalized: &str) -> usize`
     - **Concrete Step-by-Step Procedure:**
       1. **Pre-Validation:** Collect `orig_chars = original.chars().collect::<Vec<char>>()`. Let `norm_len = normalized.chars().count()`. Clamp `c = original_cursor.min(orig_chars.len())`.
          - If `c == 0`, return `0`.
          - If `c == orig_chars.len()`, return `norm_len`.
       2. **Detect Cross-Boundary Two-Part Vowel Collapse:**
          In Bengali NFC, canonical composition occurs when `U+09C7` (`ে`) is immediately followed by `U+09BE` (`া`) to form `U+09CB` (`ো`), or by `U+09D7` (`ৗ`) to form `U+09CC` (`ৌ`).
          Test if the cursor sits directly between such a collapsing pair:
          `is_cross_boundary = c > 0 && c < orig_chars.len() && orig_chars[c - 1] == '\u{09C7}' && (orig_chars[c] == '\u{09BE}' || orig_chars[c] == '\u{09D7}')`.
       3. **Compute Mapped Position via Left-Affinity (Trailing Absorption):**
          - If `is_cross_boundary` is `true`:
            The cursor sits between the leading mark (`ে`) and the trailing mark (`া`/`ৗ`) that fuse into `ো`/`ৌ`. Under **Left-Affinity**, the trailing character is absorbed into the preceding unit so the cursor lands immediately **after** the newly formed composed vowel.
            Compute prefix length using effective prefix `&orig_chars[0..=c]` (which includes the trailing mark):
            $$\text{mapped\_pos} = \text{normalize\_nfc}(\text{&orig\_chars}[0..=c].\text{iter}().\text{collect}()).\text{chars}().\text{count}()$$
          - If `is_cross_boundary` is `false`:
            The collapse (if any) occurs strictly on one side of the cursor. The prefix `&orig_chars[0..c]` does not split a collapsing composite:
            $$\text{mapped\_pos} = \text{normalize\_nfc}(\text{&orig\_chars}[0..c].\text{iter}().\text{collect}()).\text{chars}().\text{count}()$$
       4. **Post-Validation:** Return `mapped_pos.min(norm_len)`.
     - **Concrete Test Assertions:**
       - *Strictly Before Cursor:* `map_cursor_after_normalization("কোখ", 3, "কোখ") == 2` (cursor was after `া`, before `খ`; moves from index 3 to index 2 after `ো`).
       - *Strictly After Cursor:* `map_cursor_after_normalization("খকো", 1, "খকো") == 1` (cursor was after `খ`; stays at index 1).
       - *Cross-Boundary (Between `ে` and `া`):* `map_cursor_after_normalization("কো", 2, "কো") == 2` (cursor was between `ে` and `া`; trailing absorption places cursor after `কো`).
       - *Nukta Invariant:* Since `ড + ়` is an NFC composition exclusion, `original = "ড়"` normalizes to `"ড়"` (length 2), and `map_cursor_after_normalization("ড়", 1, "ড়") == 2` (cursor was after atomic `ড়`; stays after decomposed `ড়`).
   - **Orphan Combining Mark Handling:**
     - Isolated vowel signs or modifiers in provisional preedit are retained as valid Unicode scalars without synthesizing artificial consonants (OpenType shapers render them with standard dotted circles `◌া` until resolved or committed).
   - **Sandbox Rendering & Font Shaping Reality:**
     - In web DOM rendering (Tauri / WebView2), splitting preedit text into separate DOM text spans around an inline caret inherently divides the text run. If the caret is placed inside a conjunct or before a combining mark, the DOM boundary breaks font shaping across the split.
     - M2 uses a practical dual-verification approach:
       1. The interactive typing area maintains the inline caret for user position feedback.
       2. A dedicated font-shaping test panel renders unbroken continuous text tokens for complex conjuncts (`ক্ষ`, `জ্ঞ`, `স্ক্র`, `হ্ম`) to visually verify OpenType ligature formation.
       3. Visual shaping is verified manually on Windows across installed fonts (e.g. Kalpurush, Nirmala UI).

6. **Layered Golden Test Suite (`crates/borno-core/tests/unicode_golden_tests.rs`):**
   - Layer 1: **Unicode Normalization Tests:**
     - Pure ASCII preservation (`NFC(ascii) == ascii`).
     - Already-normalized idempotency (`NFC(s) == s`).
     - Independent vowel composition tests: isolated two-part signs (`\u{09C7}\u{09BE} ➔ \u{09CB}`, `\u{09C7}\u{09D7} ➔ \u{09CC}`) and base-consonant syllables (`ক + ে + া ➔ কো`, `ক + ে + ৗ ➔ কৌ`).
     - Standard nukta canonical decomposition in committed text: verify `ড়`, `ঢ়`, `য়` decompose under strict NFC to `ড + ়`, `ঢ + ়`, `য + ়`, and verify `ড + ়` remains `ড + ়`.
     - Mixed-script normalization: verify decomposable mixed string `"Node.js \u{0995}\u{09C7}\u{09BE}ড"` normalizes to `"Node.js কোড"`, while already-normalized mixed string `"Version 2.0: \u{09AC}\u{09BE}\u{0982}\u{09B2}\u{09BE}"` remains strictly byte-identical.
   - Layer 2: **Bangla Character Classification Tests:**
     - Exhaustive verification of all 96 assigned code points in `U+0980..U+09FF` against UCD 16.0.0 (38 consonants, 14 vowels, 14 vowel signs, 5 modifiers, 10 digits, 15 additional) with verified zero category overlap and zero omissions.
     - Explicit verification that all 32 unassigned code points return `false` for assigned categories.
     - Verification of UCD properties vs. Borno IME typing categories (including `UncategorizedBengali`).
   - Layer 3: **Grapheme Segmentation & Cursor Tests:**
     - UAX #29 cluster boundaries on simple and complex syllables.
     - Bidirectional codepoint-to-cluster mapping.
     - Deterministic cursor mapping under normalization across all conditions:
       - Test normalization strictly before the cursor.
       - Test normalization strictly after the cursor.
       - Test cross-boundary normalization (cursor between `ে` and `া`).
       - Test nukta normalization cursor mapping.
   - Layer 4: **Composition Policy Tests:**
     - Conjunct codepoint sequences (`ক্ষ`, `জ্ঞ`, `ত্র`, `ঙ্ক`, `ঙ্গ`, `ঞ্চ`, `ঞ্জ`, `ণ্ড`, `ন্ত`, `ন্দ`, `ম্প`, `ম্ব`, `ষ্ট`, `স্থ`, `স্প`, `স্ক্র`, `হ্ম`).
     - Reph and Phalas.
     - Direct atomic Khanda-Ta (`ৎ` `U+09CE`) input policy.
     - Independent joiner preservation tests for ZWNJ (`U+200C`) and ZWJ (`U+200D`).
     - Isolated legacy compatibility tests for explicit helper `convert_legacy_khanda_ta("ত\u{09CD}\u{200D}")` ➔ `"ৎ"`.
   - Layer 5: **Sanitization & Regression Tests:**
     - Context-scoped consecutive hasanta collapsing (and preservation when joiners are present).
     - Context-scoped vowel sign replacement on the same syllable.
     - Zero mutation of committed document text.
     - Mixed-script and punctuation preservation.

### Explicit Non-Goals

- Full Avro-compatible phonetic transliteration table, corpus dictionary lookups, or ambiguity scoring (deferred to M3).
- Fixed keyboard layouts (Bijoy, National, Probhat) (deferred to M4).
- System-wide Windows IME TSF hooks or elevated installation (deferred to M7/M12).
- Custom font glyph rendering or building a custom OpenType font shaper (rendering is delegated to host OS HarfBuzz/DirectWrite).

## 7. Stop Conditions & Risk Management

- **Regression Stop:** If Unicode normalization or classification changes cause any of the 29 baseline tests (unit, contract, or FFI) to fail, halt immediately and resolve before proceeding.
- **Dependency Vetting:** Before adding `unicode-normalization` or `unicode-segmentation`, verify offline compilation and license compatibility (MIT/Apache-2.0). If an external crate introduces build blockers under the MinGW environment, implement the required standard tables in pure self-contained Rust.
- **Rendering Boundary:** Never attempt to generate private-use or pre-rendered glyph codes for conjuncts. The engine's contract ends at valid canonical Unicode sequences; ligature rendering belongs exclusively to font shapers.
- **Execution Gate:** M2 is complete only when all 9 acceptance criteria are verified and the completion report is approved.
