## Scope

### Planned Outcomes
- Inspect the actual repository, environment, Rust toolchain, native compiler, and Windows SDK.
- Validate a minimal Rust-to-native FFI boundary with documented memory ownership, error handling, and safe UTF-8 Bangla Unicode input/output.
- Investigate the Windows Text Services Framework (TSF) COM architecture, interface pipeline, registration requirements, and permission levels.
- Build and test a minimal native TSF in-process COM prototype, distinguishing compilation, export validation, class factory validation, registration, activation, and typing.
- Explicitly document registration permissions and blockers without weakening acceptance criteria or fabricating success.
- Preserve the runnable M0 desktop sandbox and keep all existing automated tests passing.
- Maintain honest platform accounting for Linux and macOS.

### Completed Outcomes
1. **Toolchain & Environment Inspection:**
   - Default toolchain: `rustc 1.99.1` (`stable-x86_64-pc-windows-gnu`).
   - Native C++ compiler: `g++.exe 16.2.0` (MinGW-w64 with POSIX UCRT).
   - TSF headers verified present: `msctf.h` and `ctfutb.h`.
   - Windows Kits standalone SDK is absent; WSL is absent (`wsl --list` confirms not installed); macOS hardware is absent.
2. **C-Compatible FFI Interface & Memory Contract:**
   - Implemented `crates/borno-core/src/ffi.rs` exporting clean C-ABI functions for engine lifecycle, status queries, event dispatch, and explicit memory cleanup.
   - Created public C header `crates/borno-core/include/borno.h`.
   - Designed direct UTF-8 round-trip test function `borno_ffi_echo_utf8` to test FFI memory safety and multi-byte Bangla Unicode preservation (`"অ"`, `"কা"`, `"ক্ষ"`, `"বাংলাদেশ"`, `"আমার সোনার বাংলা"`) completely decoupled from engine transliteration rules.
   - 5 automated FFI unit/integration tests added in `crates/borno-core/tests/ffi_tests.rs`; all pass with 0 failures.
3. **Windows TSF Architecture Specification:**
   - Authored `docs/windows-tsf-architecture.md` defining the 6 explicit verification levels, COM lifecycle, composition editing sequence, registration permissions, and architectural boundaries.
4. **Native TSF In-Process COM Prototype Spike (`native/borno-tsf`):**
   - Built self-contained native DLL `borno_tsf.dll` implementing standard COM entry points (`DllGetClassObject`, `DllCanUnloadNow`, `DllRegisterServer`, `DllUnregisterServer`) and `ITfTextInputProcessor`.
   - Linked statically against `libborno_core.a` (Rust engine) and MinGW runtime (`-static -static-libgcc -static-libstdc++`) to prevent missing DLL failures in host processes.
   - Built standalone C++ test harness `test_harness.exe` validating Levels 1, 2, 3, and investigating Level 4.
5. **Registration & Permission Investigation:**
   - Per-user COM registration in `HKCU\Software\Classes\CLSID` succeeded without elevation.
   - TSF profile registration (`ITfInputProcessorProfiles::Register`) returned `0x80004005` (`E_FAIL`) due to Windows system TSF registry permission requirements (`HKLM\SOFTWARE\Microsoft\CTF\TIP`), proving that system-wide TSF profile registration requires administrator elevation via an installer (scheduled for M12).
6. **M0 Baseline Integrity:**
   - All 11 core engine tests continue to pass.
   - Full workspace `cargo test` passes (16 tests total in `borno-core`).
   - Frontend `npm run build` succeeds cleanly.
   - Standalone desktop sandbox remains fully runnable.

### Deferred Outcomes and Reasons
- **Level 5 (Profile Activation) & Level 6 (System-wide Typing):** Intentionally scoped to M7 (First Native IME — Windows). A full system IME requires text store range manipulation, composition display attributes, and candidate UI integration.
- **Linux Native Integration:** Documented as `Unverified / Environment Not Available` because WSL and local Linux environments are not installed on this host.
- **macOS Native Integration:** Documented as `Unverified / Hardware Not Available` due to lack of macOS hardware.

## Known Issues and Limitations

1. **TSF Profile System Registration Requires Elevation:**
   While COM classes can be registered in per-user hives (`HKCU\Software\Classes\CLSID`), registering as an active Windows Text Service profile via `ITfInputProcessorProfiles::Register` requires writing to `HKLM\SOFTWARE\Microsoft\CTF\TIP`, which returned `0x80004005` under standard user permissions. This confirms that system-wide input method installation must be executed via an elevated installer (WiX MSI or NSIS) during M12.
2. **MinGW Header Versioning:**
   MinGW-w64's `msctf.h` provides the standard `ITfTextInputProcessor` interface, but does not declare `ITfTextInputProcessorEx` (added in Windows 8 for extended activation flags). For M7, we can either manually declare the `ITfTextInputProcessorEx` vtable extension or configure MSVC build tools if Windows Store / AppContainer certification is required.
3. **Platform Availability:**
   Linux and macOS testing remains unverified due to lack of local WSL/Linux VM and Mac hardware.
