## 1. Milestone Purpose, Scope & Architectural Boundaries

### 1.1 Purpose
Introduce a dedicated, data-driven **Fixed Keyboard Layouts Engine** into the pure Rust core (`crates/borno-core/src/layout/`), strictly decoupled from the phonetic transliteration engine (`crates/borno-core/src/phonetic/`). This engine provides deterministic physical and virtual keyboard input across three standard Bengali keyboard layouts:
1. **National / Jatiya Layout (Provisional BCC Baseline):** Standard layout based on Bangladesh Computer Council (BCC) specifications and XKB `symbols/bd` (`basic` variant).
2. **Probhat Layout (Verified Upstream Conformance):** Open-source phonetic-geometry layout created by Golam Mohammad Murtuza (2001), verified against upstream GNU `m17n-db` (`MIM/bn-probhat.mim`) and `xkeyboard-config` (`symbols/in`, `ben_probhat`).
3. **Bijoy-Compatible Layout (Provisional Unicode Baseline):** Traditional desktop publishing physical geometry adapted strictly for standard modern Unicode code point emission (NFC), based on the open-source OmicronLab Avro baseline.

### 1.2 Strict Scope Separation: M4 (Fixed Layouts) vs. M5 (Settings) & M6 (Dictionary)

- **M4 delivers:** Deterministic physical key-event mapping and composition. Layout definitions are data structures validated against a strict schema.
- **M4 does NOT include disk persistence or custom file pickers:** Layouts in M4 are compiled into the core engine with a JSON schema validator ready for user files in M5. Layout selection is managed in-memory via the engine contract.
- **Zero Coupling with Phonetic Transliteration:** The layout engine operates independently in `crates/borno-core/src/layout/`. The phonetic sub-crate (`crates/borno-core/src/phonetic/`) remains untouched and unaffected.
- **No Proprietary Legacy Font Glyphs:** Borno emits only canonical standard Unicode in NFC. Legacy non-standard ANSI font glyph sequences (e.g. SutonnyMJ ANSI codes) are strictly rejected.

### 3.2 Physical Key Identifiers, Count & Layer Architecture

#### Exact Physical Key Count Specification: 48 Total Physical Keys
To eliminate any ambiguity between alphanumeric keys, punctuation keys, and whitespace delimiters, the physical keyboard matrix is formally partitioned into:
- **47 Alphanumeric & Punctuation Keys:** Character-producing keys across rows E, D, C, and B.
- **1 Whitespace Delimiter Key (`Space`):** The space bar key, producing `U+0020` and triggering active preedit commit.
- **Total Physical Keys:** Exactly **48 keys** represented in the `PhysicalKey` enum.

```
Row E (Number Row)  : Backquote, Digit1..Digit0 (10 keys), Minus, Equal           = 13 keys
Row D (Upper Row)   : KeyQ..KeyP (10 keys), BracketLeft, BracketRight, Backslash  = 13 keys
Row C (Home Row)    : KeyA..KeyL (9 keys), Semicolon, Quote                      = 11 keys
Row B (Bottom Row)  : KeyZ..KeyM (7 keys), Comma, Period, Slash                  = 10 keys
Row A (Space Row)   : Space                                                       =  1 key
──────────────────────────────────────────────────────────────────────────────────────────
TOTAL PHYSICAL KEYS :                                                             = 48 keys
```

#### Layer Support & Requirements per Layout

| Layout | Normal (Layer 1) | Shift (Layer 2) | AltGr (Layer 3) | Shift+AltGr (Layer 4) |
|---|:---:|:---:|:---:|:---:|
| **National (Jatiya)** | **Required** (48 keys) | **Required** (48 keys) | **Partial** (3 keys: `Digit4` → `$`, `Digit7` → `&`, `Equal` → `॥`) | **Explicitly Excluded** |
| **Probhat** | **Required** (48 keys) | **Required** (48 keys) | Not Used (`None` across all keys) | **Explicitly Excluded** |
| **Bijoy-Compatible** | **Required** (48 keys) | **Required** (48 keys) | Not Used (`None` across all keys) | **Explicitly Excluded** |

#### Technical Rationale for Excluding Shift+AltGr (Level 4):
1. **Ergonomic Strain:** Holding three physical keys simultaneously (`Shift + AltGr + Key`) causes high user fatigue and error rates.
2. **OS Shortcut Collisions:** `Shift+Ctrl+Alt` key combinations frequently collide with system shortcuts and window management hotkeys across Windows, GNOME, KDE, and browser environments.
3. **Redundancy:** Layers 1–2 and the link-key composition state machine provide 100% coverage of the Bengali script, punctuation, currency symbols, and formatting joiners.

#### Distinguishing Genuine AltGr from Ctrl+Alt Shortcuts
On Windows, the operating system keyboard driver translates physical Right Alt (AltGr) by injecting a synthetic `VK_CONTROL` followed immediately by `VK_MENU` (Alt). Naive event listeners mistake this for `Ctrl + Alt`. Borno enforces strict differentiation across supported event sources:
- **Web / Tauri DOM Events (Desktop Sandbox):** The UI listener inspects `event.getModifierState("AltGraph")`. If `true`, the event is classified as genuine `AltGr`. If `event.ctrlKey && event.altKey` is true but `event.getModifierState("AltGraph")` is `false`, the event is recognized as an application accelerator/shortcut (e.g. `Ctrl+Alt+S`), and the engine leaves preedit untouched.
- **Native Win32 Event Dispatch (C-ABI):** AltGr is identified by verifying the extended key flag `(lParam & (1 << 24))` or checking that `GetKeyState(VK_RMENU) < 0` is set, distinguishing it from physical Left Control + Left Alt.

### 4.4 Unified Event Path: Physical & Virtual Keyboard Parity
- **Zero UI Bypassing:** Both physical keypresses (captured via hardware scan codes or `event.code`) and virtual on-screen keyboard clicks construct the **exact same** `EngineEvent::InputKey { key, modifiers }` event and dispatch it through `BornoEngine::process_event()`. The UI never manipulates the composition buffer directly.
- **Deduplication:** Browser and desktop window listeners hook `keydown` and call `event.preventDefault()` to stop the host OS or webview from dispatching a secondary `keypress`/`input` character event for the same physical stroke.
- **Repeat Handling:** Hardware key-repeat events emit sequential `InputKey` events, which are processed deterministically by the layout engine.
- **Unsupported Layers & Modifiers:** 
  - Any event with `modifiers.shift == true && modifiers.altgr == true` (Level 4) is rejected as an unsupported layer (`handled = false`, preedit untouched).
  - Any event with `modifiers.ctrl == true` or `modifiers.alt == true` (without AltGr) is recognized as an application accelerator (e.g. `Ctrl+C`, `Alt+Tab`). The engine leaves preedit untouched and returns `handled = false`, `committed: None`.
- **Limits of Cross-Platform Physical Key Consistency:** Standard ANSI 101/104-key physical geometry is targeted. On non-standard hardware (e.g. European ISO keyboards with `<LSGT>` next to Left Shift, or Japanese JIS keyboards), non-ANSI keys are treated as unmapped passthrough.

## 5. Composition Semantics & Exhaustive Edge Cases

The Fixed Layout Engine maintains a deterministic 2-state machine: `Idle` and `LinkPending`.

```
          ┌────────────────────────────────────────────────────────┐
          │                      STATE: Idle                       │
          │  - Normal consonant / vowel / digit keys emit directly  │
          │  - Emits in standard Unicode canonical order (NFC)      │
          └───────────┬────────────────────────────────▲───────────┘
                      │                                │
      Link Key Typed  │                                │ Consonant typed (conjunct)
      (National/Bijoy: 'g',                            │ or Vowel sign typed (vowel)
       Probhat: '/')  │                                │ or Backspace typed (cancel link)
                      ▼                                │
          ┌────────────────────────────────────────────┴───────────┐
          │                   STATE: LinkPending                   │
          │  - Hasanta '্' (U+09CD) is active at cursor            │
          │  - Next consonant creates conjunct ligature            │
          │  - Next vowel sign transforms into independent vowel   │
          │    (National & Bijoy only)                             │
          └────────────────────────────────────────────────────────┘
```

### 5.1 Orthographic Policies for Composition
1. **Leading-Virama Output Policy (Empty-Text Start + Link Key + Consonant):**
   - In Unicode Bengali, an initial combining virama `্` (`U+09CD`) without a preceding consonant base is orthographically defective and invalid (it renders as an unsightly dotted-circle placeholder `◌্ক`). No valid Bengali word or syllable begins with a virama.
   - *Justified Policy:* When the preedit buffer is empty (`cursor == 0`), pressing the link key transitions to `LinkPending` (`preedit = "্"`, `cursor = 1`).
     - If followed by a vowel sign (`KeyF` / `া` in National/Bijoy): it transforms into the independent vowel `আ` (`cursor = 1`, `state = Idle`).
     - If followed by a consonant (`KeyJ` / `ক` in National/Bijoy): the engine **discards the defective leading virama** and emits the consonant as a clean base character (`preedit = "ক"`, `cursor = 1`, `state = Idle`). This guarantees that user text is never polluted with invalid dotted-circle sequences.
     - If followed by Space: the dangling virama is discarded, committing `" "`, with `preedit = ""`, `cursor = 0`, `state = Idle`.
     - If followed by Backspace: the Hasanta is deleted, returning `preedit = ""`, `cursor = 0`, `state = Idle`.
2. **Contextual Link-Key Vowel Transformation Policy:**
   - In **National** and **Bijoy**, physical keyboards lack dedicated keys for independent vowels (`আ`, `ই`, `ঈ`, `উ`, `ঊ`, `ঋ`, `এ`, `ঐ`, `ও`, `ঔ`). The link key `g` followed by a vowel sign is the established input convention for generating independent vowels.
   - *Context Scope:* This transformation occurs in **all valid composition contexts**:
     - At text start: `g + া` → `আ`.
     - Medial after consonant: `ব + g + ি` → `বই` (`cursor = 2`, `state = Idle`).
     - Medial after consonant: `য + g + া` → `যআ` (`cursor = 2`, `state = Idle`).
     - Contrast with dependent vowel signs: dependent vowel signs (kars) are always typed *directly without the link key* (e.g. `ব + ি` → `বি`).
   - In **Probhat**, `supports_link_vowel_composition == false`. Probhat provides dedicated physical keys for independent vowels (`KeyV` = `আ`, `KeyI` = `ই`, etc.). If a user types link key `/` followed by a vowel sign (`KeyA` / `া`), M2 sanitization replaces the Hasanta with the vowel sign, producing dependent kar `কা` (`cursor = 2`, `state = Idle`).

### 5.3 Logical Unicode Order vs. Visual Shaping
- **Pure Phonetic / Logical Codepoint Emission:** The engine strictly stores, manipulates, and emits text in **logical Unicode order** (e.g. `ক` + `ি` = `কি` `U+0995\u{09BF}`, `র` + `্` + `ক` = `র্ক` `U+09B0\u{09CD}\u{0995}`).
- **Zero Visual Reordering in Core:** The engine **never** reorders codepoints to mimic visual glyph positions (such as placing `ি` or `ে` before the base consonant, or drawing Reph).
- **Decoupled Text Shaping:** Visual glyph reordering, ligature substitution (e.g. rendering `ক` + `্` + `ষ` as single glyph `ক্ষ`), and contextual mark positioning are exclusively performed downstream by standard OpenType text shaping engines (DirectWrite on Windows, HarfBuzz on Linux, CoreText on macOS).
- **Intentional Codepoint Deconstruction on Backspace:** Backspace operates on Unicode codepoints rather than extended grapheme clusters. When deleting the trailing consonant of a conjunct (`ক্ষ` → `ক্`), the engine detects that the preceding character is Hasanta `্` (`U+09CD`) and **automatically transitions back to `LinkPending` state**. The user can immediately type a replacement consonant (e.g. `ক` to form `ক্ক`) without retyping the initial consonant and link key.

### 6.1 Schema Data Structures (`crates/borno-core/src/layout/schema.rs`)

```rust
    pub unshifted: String,                  // Required non-empty string for all 48 keys
    pub shifted: String,                    // Required non-empty string for all 48 keys
    pub altgr: Option<String>,              // Permitted only when AltGr is declared in supported_layers
}

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
pub struct LayoutRules {
    pub link_key: Option<PhysicalKey>,           // KeyG in National/Bijoy, Slash in Probhat
    pub supports_link_vowel_composition: bool,   // true for National & Bijoy ('g' + 'া' -> 'আ')
    pub link_vowel_map: BTreeMap<String, String>,// e.g. "া" -> "আ", "ি" -> "ই"
}

#[derive(Debug, Clone, Serialize, Deserialize, PartialEq, Eq)]
pub struct LayoutDefinition {
    pub schema_version: String,  // "1.0.0"
    pub metadata: LayoutMetadata,
    pub rules: LayoutRules,
    pub keys: BTreeMap<PhysicalKey, KeyMapping>,
}
```

### 6.2 Strict Schema Validation Policy
In Rust, `String` types are guaranteed to be valid UTF-8 by type invariant. Validation enforces script boundaries, completeness, and structural integrity:

1. **Schema Version Check:** `schema_version` must equal `"1.0.0"`.
2. **Identifier Format:** `metadata.id` must match `^[a-z0-9_-]+$` and contain 2 to 32 characters.
3. **Exhaustive Key Completeness:** All 48 physical keys (`PhysicalKey::Backquote` through `PhysicalKey::Space`) must have both `unshifted` and `shifted` present and non-empty. For `PhysicalKey::Space`, `unshifted = " "` and `shifted = " "`.
4. **Per-Layout AltGr Layer Enforcement:**
   - If `ModifierLayer::AltGr` is not in `metadata.supported_layers` (e.g. Probhat and Bijoy), the validator asserts that all 48 keys have `altgr == None`. Any key with `altgr.is_some()` returns `Err(LayoutError::UnexpectedLayerMapping { key, layer: ModifierLayer::AltGr })`.
   - If `ModifierLayer::AltGr` is in `metadata.supported_layers` (e.g. National), `altgr` is permitted only on declared keys (`Digit4`, `Digit7`, `Equal`). If any other key defines `altgr`, the validator returns `Err(LayoutError::UnexpectedLayerMapping)`.
5. **Rejection of Unsupported Shift+AltGr (Level 4):**
   - The schema intentionally defines no `ShiftAltGr` modifier layer.
   - At runtime, `FixedLayoutEngine::process_key` rejects any key event where `modifiers.shift == true && modifiers.altgr == true` (`handled = false`, preedit untouched).
6. **Allowed Codepoint Policy:** Every character in `unshifted`, `shifted`, and `altgr` must fall strictly within:
   - Bengali script block: `U+0980`..`U+09FF`
   - Common Indic & formatting signs: `U+0964` (Dari), `U+0965` (Double Dari), `U+200C` (ZWNJ), `U+200D` (ZWJ)
   - Printable ASCII: `U+0020`..`U+007E`
   - Disallowed: Any control code (`U+0000`..`U+001F`, `U+007F`..`U+009F`) or foreign script blocks.
7. **Validation Error Enumeration:**
   ```rust
   #[derive(Debug, Clone, PartialEq, Eq)]
   pub enum LayoutError {
       UnsupportedSchemaVersion { expected: String, found: String },
       InvalidMetadataId(String),
       MissingKeyMapping(PhysicalKey),
       MissingShiftMapping(PhysicalKey),
       EmptyMapping(PhysicalKey, String),
       DisallowedCodePoint { key: PhysicalKey, layer: String, ch: char, codepoint: u32 },
       UnexpectedLayerMapping { key: PhysicalKey, layer: ModifierLayer },
       DuplicateDefinition(String),
       SerializationError(String),
   }
   ```

## 7. Dual-Mode Switching & State Machine Integration (`crates/borno-core/src/lib.rs`)

### 7.1 Invariants on Mode Switch
- **Auto-Commit on Mode Switch:** If the engine receives `EngineEvent::SwitchMode(new_mode)` while `is_composing == true`, the active preedit buffer is immediately committed as normalized NFC text (`ProcessResult.committed = Some(state.preedit.clone())`).
- **Buffer & Cursor Reset:** Following the auto-commit, `preedit`, `raw_buffer`, and `cursor_pos` reset cleanly to 0. `is_composing` resets to `false`.
- **Zero Heap Allocation on Hot Path:** Built-in layouts are instantiated at compile time (`builtin::NATIONAL_LAYOUT`, `builtin::PROBHAT_LAYOUT`, `builtin::BIJOY_LAYOUT`). Switching layouts sets an internal pointer `&'static LayoutDefinition` with zero heap allocation.

## 12. Stop Conditions & Risk Management

- **Regression Stop:** If any of the 117 baseline tests fail during M4 development, halt immediately and resolve before proceeding.
- **Legacy ANSI Boundary:** Do not emit legacy non-standard font glyph codes (e.g. SutonnyMJ ANSI codes). All output from the fixed layout engine must remain 100% standard Unicode in NFC.
- **Settings Creep Stop:** Do not introduce disk-based file saving or file pickers for layouts in M4. Keep layout selection in-memory; disk persistence is strictly scheduled for Milestone M5.
- **Execution Gate:** Milestone M4 is complete only when all 9 acceptance criteria are verified and its completion report is approved.
