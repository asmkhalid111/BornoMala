## 1. Executive summary

### 1.1 Verdict

**The foundation is genuinely good; the verification layer around it is not yet trustworthy.**

The project has a real, working architecture: a pure Rust core with a documented event/state contract, three mode-specific state machines (phonetic, fixed layouts, passthrough), a trie dictionary, a real Windows TSF in-process COM text service, a real Linux Fcitx 5 addon, and a runnable Tauri + React sandbox. On this machine I independently reproduced:

- `cargo test --workspace` → **232 core tests passed, 0 failed** (the documented 4-minute run).
- `cargo run -p bornomala-desktop --bin persistence_suite` → **8/8 persistence tests passed**.
- `npm run build` → **TypeScript + Vite production build succeeded** with the exact bundle hashes the M9 report claims.
- Launching `Borno-Sandbox.exe` → **the app runs** (30 MB working set, window created).
- The Windows TSF text service is **registered on this machine** (CLSID `{8A57F89C-3BF7-4B9E-A79B-86DF372E4F01}` → `native/borno-tsf/bornomala_tsf.dll`).

That is a legitimate base to continue from.

However, the audit found **eight P0 defects**, of which four are disqualifying for a “Verified” status of the current milestone:

1. The **production candidate generator contains hard-coded answers for the test suite** (`"ka"` → `কা/ক্যা/খা`, `"tumi"` → `তূমি`), and the tests that assert them are the very tests cited as evidence. This directly violates `AGENTS.md` §1.3 (“No Decorative Placeholders”).
2. The **phonetic editing cursor mixes byte offsets with character indices**, so paste/IME input containing non-ASCII text is silently mis-edited (a deletion can do nothing and still report `handled = true`).
3. **Settings never reach either native IME.** The desktop writes `%APPDATA%\com.bornomala.sandbox\config.json`; both adapters read `com.bornomala.desktop\config.json`. I confirmed only the former directory exists on this machine, so the “live configuration reload” feature is inert end-to-end.
4. **M7 is marked “Verified” in the roadmap while its own completion report says Level 5 and Level 6 (language-bar activation and end-to-end system typing) are `PENDING`** and its next step is “developer interactive verification … formal sign-off”. The roadmap’s claim of testing in Notepad/Sublime/Office/VS Code is not supported by any evidence in the repository.

Also P0: Windows TSF composition lifetime is unsafe (compositions are released, not ended, on deactivate/focus change — a plausible use-after-free inside host applications), the toggle key steals plain `F12`/`F4`/`Alt+F4` and Shift+digit commits candidates, `build.ps1` silently unregisters the user’s installed IME, and the CC BY 4.0 lexicon is redistributed without any attribution/NOTICE file even though the license document claims attribution exists.

## 2. The plan as written

The project’s master plan (`ROADMAP.md`) is unusually rigorous on paper. In summary:

- **Product:** offline-first, privacy-preserving Bangla input platform; phonetic + fixed layouts; shared Rust core; native IMEs on Windows/Linux/macOS; dictionary assistance; settings; `v1.0.0` target.
- **Architecture:** Rust core → C-ABI → thin native adapters (TSF on Windows, Fcitx 5 on Linux, InputMethodKit on macOS) + Tauri/React sandbox and settings app.
- **Governance:** one milestone at a time; no spec for a future milestone written in advance; explicit evidence states; every milestone keeps the app runnable; a completion report with commands and real outputs.
- **Three version domains:** product milestones (`M0…M13`), UX (`UX 0.1.0`), config schema (`1.2.0`).
- **Milestones:** M0 foundation, M0.1 feasibility, M1 contract, M2 Unicode, M3 phonetic, M4 layouts, M5 settings, M6 dictionary, M7 Windows TSF, M8 Linux, M9 customization, M10 prediction (optional), M11 hardening, M12 packaging, M13 release.
- **Definition of done:** acceptance criteria + automated tests + manual checks + runnable checkpoint + roadmap updated from evidence.

The plan itself is good. The gap is between the plan and what the repository evidences.

## 5. Findings

### 5.1 P0 — Release-blocking

#### P0-1. The production candidate generator contains hard-coded test answers

**Evidence:** [`candidates.rs:27-28`](../crates/bornomala-core/src/phonetic/candidates.rs#L27-L28) and [`candidates.rs:73-80`](../crates/bornomala-core/src/phonetic/candidates.rs#L73-L80):

```rust
// Backward Compatibility Fixtures for Engine Contract Tests
if raw_buffer == "k" { push "খ" }
else if raw_buffer == "ka" { push "ক্যা"; push "খা" }
```
and
```rust
if raw_buffer == "tumi" { Self::push_if_unique(&mut candidates, "তূমি".to_string()); }
```

`ক্যা`/`খা`/`তূমি` are not derivable from any phonetic rule. The contract tests then assert exactly these values ([`contract_tests.rs:148-151`](../crates/bornomala-core/tests/contract_tests.rs#L148-L151), [`engine_config_tests.rs:15-31`](../crates/bornomala-core/tests/engine_config_tests.rs#L15-L31)).

**Impact:** the candidate panel shows fabricated entries for two of the most common inputs (`k`, `ka`), and the tests that are supposed to protect candidate generation instead certify the fabrication. This is precisely the “decorative placeholder” pattern `AGENTS.md` §1.3 forbids. It also masks real rule regressions.

**Fix:** delete both blocks; re-baseline the affected tests on genuine rule output; add a test asserting that candidate generation for a corpus of inputs produces only rule-derived candidates. **Cost: 0.5 day.**

#### P0-2. Byte offset / character index conflation in phonetic editing

**Evidence:** `source_cursor` is documented as a byte offset ([`lib.rs:1286-1293`](../crates/bornomala-core/src/lib.rs#L1286-L1293), [`lib.rs:659`](../crates/bornomala-core/src/lib.rs#L659)) but is used as a `Vec<char>` index and re-assigned with `len_utf8()` in the same function:

- [`lib.rs:1311-1316`](../crates/bornomala-core/src/lib.rs#L1311-L1316) (`insert_char_at_cursor`)
- [`lib.rs:1327-1335`](../crates/bornomala-core/src/lib.rs#L1327-L1335) (`delete_before_cursor`)
- [`lib.rs:1347-1352`](../crates/bornomala-core/src/lib.rs#L1347-L1352) (`delete_after_cursor`)

**Impact:** for ASCII input the two units coincide and everything works. For the advertised `InputString` (paste) path with any Bangla text, the cursor arithmetic goes out of range: a backspace can delete nothing, jump the cursor to 0, and still return `handled = true`. That is silent text corruption inside the host process.

**Fix:** introduce `ByteOffset`/`CharIndex` newtypes (or convert with `char_indices()` at each boundary), add property tests over mixed ASCII/Bangla buffers. **Cost: 1–2 days.**

#### P0-3. Settings never reach the native IMEs (config path mismatch)

**Evidence:**

| Side | Path |
|---|---|
| Tauri writer | `app_config_dir()` + `config.json`; identifier `com.bornomala.sandbox` ([`tauri.conf.json:5`](../src-tauri/tauri.conf.json#L5), [`lib.rs:225-229`](../src-tauri/src/lib.rs#L225-L229)) |
| Windows adapter | `%APPDATA%\com.bornomala.desktop\config.json` ([`borno_tsf.cpp:83-86`](../native/borno-tsf/borno_tsf.cpp#L83-L86)) |
| Linux adapter | `~/.config/com.bornomala.desktop/config.json` ([`bornomala.cpp:15`](../native/bornomala-fcitx5/bornomala.cpp#L15)) |

Verified on this machine: `%APPDATA%\com.bornomala.sandbox\config.json` exists (schema 1.2.0, 13 fields); `%APPDATA%\com.bornomala.desktop\` **does not exist**.

**Impact:** the entire M9 “native configuration reload” feature — mode toggle key, theme, font size, candidate limit — is inert in the shipped IME. The user changes settings, sees them applied in the sandbox, and the IME keeps its old behaviour. This is exactly the “decorative settings” failure the roadmap §M5 forbids.

**Fix:** pick one canonical path now. Recommended: change the Tauri identifier to `com.bornomala.desktop` (as M12 already plans) and migrate an existing `com.bornomala.sandbox` file on first run; point both adapters at the same path; add an integration test that writes config from the desktop side and asserts the adapter reads it. **Cost: 1–2 days.**

#### P0-4. M7 is marked “Verified” without end-to-end evidence; two claimed M7 behaviours are not implemented

**Evidence:**

- [`M7_COMPLETION_REPORT.md:132-133`](M7_COMPLETION_REPORT.md#L132-L133): `Level 5 (Language Bar Activation): PENDING STAGE 6`, `Level 6 (End-to-End System Typing): PENDING STAGE 6`.
- [`M7_COMPLETION_REPORT.md:185`](M7_COMPLETION_REPORT.md#L185): “Developer interactive verification of Levels 4, 5, and 6 … Formal sign-off on Milestone M7.”
- [`ROADMAP.md:287`](../ROADMAP.md#L287): “tested across Windows Notepad, Sublime Text, Office, Visual Studio Code”.
- The claimed preedit underline has no `ITfDisplayAttributeProvider`, no display-attribute GUID, and no `TF_ATTR_INPUT` anywhere in `native/borno-tsf/` (grep-verified).
- The claimed “on any document mutation failure the adapter resets the engine” does not exist: `SetText`/`SetSelection`/`StartComposition` results are unchecked ([`borno_tsf.cpp:709`](../native/borno-tsf/borno_tsf.cpp#L709), `:728`, `:744`, `:776`).

**Impact:** the project’s core claim — “system-wide typing works on Windows” — is unproven, and two documented behaviours are absent. This is the clearest violation of `AGENTS.md` §2.1 (“Never claim a tool, test, build, or platform works unless you have executed the command and verified the actual output”).

**Fix:** change M7 to `Implemented — not verified`; run and record a real E2E matrix (Notepad, Word, Chrome, VS Code, Explorer rename); implement the display-attribute provider or delete the claim; add a checked-error path. **Cost: 2–3 days (including capture of evidence).**

#### P0-5. Windows TSF composition lifetime is unsafe

**Evidence:**

- `Deactivate()` releases the composition without ending it: [`borno_tsf.cpp:331-336`](../native/borno-tsf/borno_tsf.cpp#L331-L336).
- `OnSetFocus` does the same: [`borno_tsf.cpp:415-431`](../native/borno-tsf/borno_tsf.cpp#L415-L431).
- Commit/cancel call `EndComposition(ec)` and then `m_pComposition->Release()` with no re-check: [`borno_tsf.cpp:718-721`](../native/borno-tsf/borno_tsf.cpp#L718-L721), [`borno_tsf.cpp:745-748`](../native/borno-tsf/borno_tsf.cpp#L745-L748). If the framework invokes `OnCompositionTerminated` during teardown (the sink nulls the pointer at `:389-394`), the following line dereferences a null pointer.

**Impact:** a stuck “composing” range and a plausible use-after-free inside Word/Explorer/browser processes, because this DLL loads in-process. Focus changes between two documents are a routine trigger.

**Fix:** end the composition through an edit session (`RequestEditSession` → `EndComposition`, clear the attribute) before releasing; capture the pointer and null the field before `EndComposition`; guard sink re-entry with a terminating flag. **Cost: 1–2 days.**

#### P0-6. Key policy steals F12/F4/Alt+F4 and Shift+digits

**Evidence:**

- `OnTestKeyDown` eats any `wParam == m_modeToggleKey` with no modifier test: [`borno_tsf.cpp:452-455`](../native/borno-tsf/borno_tsf.cpp#L452-L455); `OnKeyDown` toggles and eats: [`borno_tsf.cpp:516-521`](../native/borno-tsf/borno_tsf.cpp#L516-L521).
- Candidate digits ignore modifiers: [`key_mapper.h:117-127`](../native/borno-tsf/key_mapper.h#L117-L127), so `!`, `@`, `#` select candidates.

**Impact:** while the IME is active, `Alt+F4` can close nothing (it toggles the mode instead), `F12` (debuggers/devtools) is hijacked in every application, and shifted punctuation cannot be typed during composition. The Fcitx adapter already guards modifiers correctly ([`bornomala.cpp:346-351`](../native/bornomala-fcitx5/bornomala.cpp#L346-L351)) — the two adapters disagree.

**Fix:** require no Ctrl/Alt/Shift for the toggle; explicitly ignore `Alt+F4`; pass the modifier state into `IsCandidateSelectionDigit`. **Cost: 0.5 day.**

#### P0-7. CC BY 4.0 attribution is missing from shipped artifacts

**Evidence:** the Leipzig-derived lexicon is embedded in the core via `include_bytes!` ([`dictionary/mod.rs:16`](../crates/bornomala-core/src/dictionary/mod.rs#L16)), so it ships inside `bornomala_tsf.dll` and `bornomala.so`. There is **no** `NOTICE`/`THIRD-PARTY` file in the repository, and neither `LICENSE-MIT` nor `LICENSE-APACHE` contains “Leipzig” or “CC BY” (grepped). Yet [`docs/resources-and-licenses.md:29`](../docs/resources-and-licenses.md#L29) claims attribution is “in the application LICENSE”.

**Impact:** redistributing the binaries without attribution breaches CC BY 4.0 §3(a) — a legal blocker for any release, and the documentation currently misstates compliance.

**Fix:** add `THIRD-PARTY-NOTICES.md` with the Leipzig citation and license URL, ship it with both installers and in the app’s About/Diagnostics, correct the doc, and add a release checklist item. **Cost: 0.5 day.**

#### P0-8. Building the project silently uninstalls the user’s IME

**Evidence:** [`build.ps1:75-79`](../native/borno-tsf/build.ps1#L75-L79) runs `test_harness.exe` unconditionally; the harness calls `DllRegisterServer` ([`test_harness.cpp:254`](../native/borno-tsf/test_harness.cpp#L254)) and then `DllUnregisterServer` ([`test_harness.cpp:273`](../native/borno-tsf/test_harness.cpp#L273)), which deletes HKLM/HKCU keys and all language profiles.

**Impact:** `build.ps1` has machine-wide side effects; a routine rebuild on a machine with the IME installed unregisters it and leaves it pointing at the build directory. It also corrupts any “clean install” test.

**Fix:** gate registration behind an explicit `--register-test` flag (and elevation), never from the build script; make a separate `scripts/register.ps1`. **Cost: 0.5 day.**

## 7. Code quality assessment: is it good enough to continue?

### 7.1 What is genuinely good

1. **The core is properly layered.** Language logic is pure Rust with no OS or GUI dependency; adapters consume a narrow C ABI; the sandbox consumes the same engine through Tauri IPC. This is the right architecture and it held across seven milestones.
2. **The Unicode/composition work is real.** 22 golden tests cover NFC, nukta decomposition, joiners, grapheme clusters and 96 assigned code points. This is more rigorous than most IME projects at this stage.
3. **The fixed-layout engine is careful.** Link-key state machine, leading-virama discard, backspace deconstruction, 48-key parity tables for three layouts, strict schema validation. 57 tests.
4. **Test volume is meaningful.** 232 tests with no `#[ignore]` and no flaky failures in this run.
5. **The persistence layer is better than typical.** Same-directory temp file, `flush`, `sync_all`, atomic rename, backup on corruption, unsupported-schema protection, migration tests.
6. **Privacy intent is explicit** and the code has no telemetry, no network calls in the core, and no default keystroke log *except* the Fcitx INFO logging noted above.
7. **Documentation practice exists**: design system, backlog, provenance, engine contract, completion reports. The intent is right even where the numbers are wrong.
8. **The TS config contract matches Rust exactly today** (13/13 fields), and `strict: true` is on with a clean `tsc --noEmit`. Nothing enforces it, but the starting point is correct.

### 7.2 What will not scale

| Debt | Why it blocks growth |
|---|---|
| Fake candidates in the engine | Any new candidate rule will be validated by tests that already accept fabricated output. Fix first. |
| Untyped cursor units | Every future editing feature (selection, word delete, undo, mobile) inherits a latent corruption bug. |
| Three hand-maintained contract copies (Rust / C / TS) | The C copy has already drifted (mode docs, error codes, `configure`); the TS config copy matches today but nothing enforces it. |
| 1,565-line engine + 1,361/1,454-line components | Feature additions are already producing duplication (four toggle blocks, three key maps). |
| No frontend/desktop tests | The UI is the largest and least-tested part of the product. |
| Adapter policy duplicated | Mode cycling, digit selection, JSON parsing and config reload exist twice with different behaviour. |
| Verification theatre | Self-rewriting fixtures, compiled-out benchmarks, unconditional PASS output. Any new “verified” is worthless until these are removed. |

## 8. What changes should have been made (retrospective)

These are process/engineering decisions that would have prevented today’s P0s. Each is stated as “decision → consequence → what it costs now”.

1. **Freeze product identity before M1.** One name (`BornoMala`), one crate directory (`crates/bornomala-core`), one header (`bornomala.h`), one bundle identifier (`com.bornomala.desktop`), one DLL name.  
   *Consequence:* duplicated 7.9 MB DLLs, two headers sharing a guard, config written to one path and read from another, docs citing `crates/borno-core`.  
   *Cost now:* ~1 day of mechanical cleanup plus a config migration test.

2. **Make “settings affect the real product” an acceptance test at M5, not a UI demo.** M5 accepted a settings drawer that changed the sandbox engine only. The native adapters were built later and invented their own path.  
   *Consequence:* P0-3, the most user-visible M9 failure.  
   *Cost now:* 1–2 days including migration.

3. **Never mark a platform milestone Verified from core tests.** M7 should have stayed `Implemented — not verified` until a logged E2E matrix existed. The roadmap should have copied the report’s status, not upgraded it.  
   *Consequence:* the project’s headline claim is unsupported, and the roadmap lost credibility.  
   *Cost now:* 2–3 days of real E2E testing and evidence capture.

4. **Ban input-specific branches in the engine.** A one-line rule in review (“no `if raw_buffer == "<literal>"` outside tests”) plus a test that generates candidates over a corpus would have prevented P0-1.  
   *Cost now:* 0.5 day.

5. **Define the cursor unit model when spans were introduced (M2/M3).** One newtype and a conversion helper would have cost an hour; the current bug survives because ASCII hides it.  
   *Cost now:* 1–2 days plus property tests.

6. **Generate the contract once.** `cbindgen` for the C header and `ts-rs`/`typeshare` for TypeScript at M1 would have removed two drift surfaces.  
   *Cost now:* 2–3 days (ABI 2.0 redesign is the right moment).

7. **Make CI verify what the milestone claims.** From M7 onward CI should have built the TSF DLL and run the persistence suite; from M8 it should have built the Fcitx addon in a container with `-UNDEBUG`.  
   *Cost now:* 2–3 days of CI work, and it is the only way to keep the claims true.

8. **Treat verification artifacts as code.** A test that rewrites its own fixtures, a benchmark compiled out in debug, and a harness that prints `PASS` unconditionally are all forms of fabricated evidence.  
   *Cost now:* 2–3 days to rebuild the verification layer honestly.

9. **Keep one roadmap and update it in the same commit as the completion report.** Archive the older `Bangla_Input_Platform_Master_Roadmap.md`; make the completion report template mandatory (the current reports already follow it, they just disagree with the roadmap).  
   *Cost now:* 0.5 day.

10. **Close milestone specs when the milestone closes.** The spec status line should move `Proposed → In progress → Verified/Blocked` in the same commit.  
    *Cost now:* 15 minutes of edits, but it restores the audit trail.

11. **Ship attribution with the first dataset (M6).** A `THIRD-PARTY-NOTICES` file costs 10 minutes when the corpus is added; it is a legal blocker later.  
    *Cost now:* 0.5 day plus a packaging dependency.

12. **Decide the installer and registration model before writing `DllRegisterServer`.** Registration from the build tree, self-unregistration in a test harness, and no Program Files copy are all consequences of deferring that decision.  
    *Cost now:* folded into M12, but P0-8 must be fixed immediately.

13. **Do not let a milestone spec become “Pass 5”.** M9 was executed in five internal passes and closed with 11 new backlog items. A milestone whose scope grows during execution is a sign the scope was wrong at approval time.  
    *Cost now:* split M9 into `M9.1`/`M9.2` (see §9) and re-baseline.
