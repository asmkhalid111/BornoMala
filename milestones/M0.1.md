## 1. Milestone Purpose and Primary Objective

- **Primary Objective:** Reduce the technical risk of Windows system-wide input integration before investing in the full Bangla input engine.
- **Purpose:** Test the highest-risk architectural assumptions regarding how the shared Rust input engine communicates with the native operating system, specifically targeting the Windows Text Services Framework (TSF) COM architecture and a stable C-compatible FFI boundary.

## 3. Scope and Explicit Non-Goals

### In-Scope
1. **C-Compatible FFI Boundary:**
   - Design a minimal, clean C-ABI (`extern "C"`) interface for `borno-core`.
   - Provide explicit memory management functions (Rust allocates, Rust frees; no allocator leaks).
   - Support UTF-8 null-terminated strings with full Bangla Unicode character safety.
   - Provide structured error reporting and status checks across the FFI boundary.
2. **FFI Verification Harness:**
   - Write automated unit and integration tests executing the C-ABI functions with deterministic Bangla transliteration inputs (`"k" + "a" -> "কা"`).
3. **Windows TSF Architecture Investigation:**
   - Document the COM interfaces required for a modern Windows Text Service (`ITfTextInputProcessor`, `ITfTextInputProcessorEx`, `ITfThreadMgr`, `ITfKeyEventSink`, `ITfComposition`, `ITfCompositionSink`, `ITfEditSession`).
   - Document registration requirements (`DllRegisterServer`, `ITfInputProcessorProfiles`, `ITfCategoryMgr`, GUIDs/CLSIDs) and privilege levels (user vs system/elevation).
   - Document architecture constraints (bitness: 64-bit vs 32-bit processes, UWP/AppContainer sandbox restrictions, thread-safety, DLL lifecycle).
4. **Minimal Native Prototype Spike:**
   - Build a minimal C++ / Rust DLL prototype implementing the entry points (`DllGetClassObject`, `DllRegisterServer`, `DllUnregisterServer`, and minimal `ITfTextInputProcessor` skeleton) to verify compilability against the available MinGW-w64 headers.
   - Clearly delineate compilation from registration and activation in real applications.
5. **Feasibility Assessment & Recommendations:**
   - Document what was successfully compiled, tested, and what requires elevated privileges or dedicated installer support for M7.

### Explicit Non-Goals
- Full TSF input method implementation (deferred to M7).
- Full phonetic parser, Avro table, or layout mappings (deferred to M3/M4).
- Candidate window GUI or floating composition toolbar (deferred to M7/M9).
- Dictionary or spellchecking assistance (deferred to M6).
- Breaking or replacing the working M0 sandbox.
- Starting M1 (Engine Contract and Sandbox) or any later milestone.

## 4. Implementation Tasks

### Task 1: TSF Architecture & COM Boundary Analysis
- Create `docs/windows-tsf-architecture.md` detailing:
  - TSF COM interface pipeline and message loop integration.
  - Composition lifecycle: Preedit text, active composition, commit, cancel.
  - Bitness & deployment: In-proc 64-bit DLL requirements.
  - COM registration process and elevated privileges requirement.
  - Exact boundary between native COM adapter and Rust engine core.

### Task 2: Minimal C-ABI Interface (`borno-core` C exports)
- Implement a focused `ffi` module in `crates/borno-core` (or a dedicated `crates/borno-ffi` crate) exporting:
  - `borno_engine_new() -> *mut BornoEngineHandle`
  - `borno_engine_free(*mut BornoEngineHandle)`
  - `borno_engine_status(*const BornoEngineHandle, *mut BornoEngineStatusC) -> i32`
  - `borno_engine_process_char(*mut BornoEngineHandle, u32, *mut BornoEngineStateC) -> i32`
  - `borno_engine_backspace(*mut BornoEngineHandle, *mut BornoEngineStateC) -> i32`
  - `borno_engine_reset(*mut BornoEngineHandle, *mut BornoEngineStateC) -> i32`
  - `borno_string_free(*mut c_char)`
- Document memory allocation rules: Any string returned across the FFI is allocated by Rust and must be released via `borno_string_free`.

### Task 3: Automated FFI Test Harness
- Write comprehensive automated tests in Rust validating the FFI functions:
  - Life cycle: allocate engine, invoke commands, free engine.
  - Unicode round-trip: pass Latin characters, receive valid UTF-8 Bangla string (`"কা"`).
  - Null pointer and error handling checks.
  - Memory leak verification (valgrind/sanitizer or deterministic allocation checks).

### Task 4: Minimal TSF Compilation Spike
- Create a minimal native C++ prototype (`native/borno-tsf/`) referencing MinGW-w64 TSF headers (`msctf.h`).
- Implement the required COM DLL exports:
  - `DllGetClassObject`
  - `DllCanUnloadNow`
  - `DllRegisterServer`
  - `DllUnregisterServer`
- Verify compilation with MinGW-w64 `g++`.
- Attempt local registration and document whether registration succeeds or requires administrator elevation.

### Task 5: Platform Assessment & Completion Report
- Record exact findings in `milestones/M0.1-completion-report.md`.
- Update `ROADMAP.md` status with evidence-based entries.

## 6. Stop Conditions & Risk Management

- **Elevation Barrier:** If `regsvr32` or COM registration requires elevated administrator privileges that cannot be granted in the current shell session, explicitly document this as a known Windows TSF platform constraint rather than fabricating registration success.
- **Regression Stop:** If any change breaks `borno-core` unit tests or the M0 desktop sandbox, immediately halt and revert before continuing.
- **Scope Limit:** Do not expand into layout parsing, candidate window UI, or dictionary implementations. Stop when the FFI boundary and TSF compilation/registration feasibility are proven.
