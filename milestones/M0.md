## 1. Milestone Identity

- **Purpose:** Establish the smallest real application that can be built, launched, and tested before feature development expands.
- **Boundaries:** This milestone covers only the initial shared Rust core library, a visible and runnable desktop sandbox application (React + TypeScript + Tauri v2), automated tests for the Rust engine, and a minimal CI configuration.
- **Explicit Non-Goals:**
  - Full Avro or phonetic transliteration engine (deferred to M3)
  - Full Bijoy, National, or other fixed keyboard layouts (deferred to M4)
  - System-wide Windows Text Services Framework (TSF) integration (M0.1 / M7)
  - Dictionary-backed word prediction or spelling correction (deferred to M6)
  - Complex preferences and theme system (deferred to M5 / M9)
  - Linux/macOS native IME integrations (deferred to M8 / later)

## 3. Goals and Explicit Non-Goals

### Goals
1. Establish a Cargo workspace with a core library crate (`borno-core`).
2. Implement a minimal deterministic engine state machine in `borno-core`:
   - Engine status query (version, active mode).
   - Normalized event processing (character input, backspace, clear/reset).
   - Preedit buffer and candidate generation for deterministic test sequences (e.g. Latin phonetic transliteration sample: "k" -> "ক", "ka" -> "কা", "r" -> "র", "kor" -> "কর").
3. Implement automated unit tests for `borno-core` passing locally.
4. Establish the desktop sandbox application (`src-tauri` + React/TS frontend):
   - Tauri v2 command handlers that directly invoke `borno-core`.
   - Real-time engine status display.
   - Interactive typing area displaying preedit composition and candidate suggestions from the Rust engine.
   - Interactive event log displaying event flows between UI and Rust core.
   - Deterministic test button to verify engine behavior interactively.
5. Provide a minimal GitHub Actions CI workflow to run automated tests.
6. Verify and record manual launch of the sandbox application on Windows.

### Explicit Non-Goals
- System-wide keyboard hooking or Windows IME installation.
- Complete phonetic rule table or dictionary loading.
- Third-party cloud analytics or external network dependencies.

## 4. Implementation Plan

### Task 1: Cargo Workspace & Core Crate Setup
- Create root `Cargo.toml` workspace configuring `crates/borno-core` and `src-tauri`.
- Create `crates/borno-core` with `Cargo.toml` and `src/lib.rs`.
- Define core types:
  - `EngineEvent` (InputChar, Backspace, Reset, Commit).
  - `EngineState` (preedit: String, candidates: Vec<String>, committed: Option<String>).
  - `EngineStatus` (name: String, version: String, ready: bool).
  - `BornoEngine` struct with `process_event(&mut self, event: EngineEvent) -> EngineState`.
- Add unit tests verifying:
  - Initial state is empty and ready.
  - Inputting deterministic characters updates preedit and candidates.
  - Backspace deletes the last character.
  - Reset clears the state.

### Task 2: Desktop Sandbox Setup (Tauri v2 + React + TypeScript)
- Set up root `package.json` with React, TypeScript, Vite, and `@tauri-apps/api`.
- Set up `src-tauri` with `Cargo.toml`, `tauri.conf.json`, and `src/lib.rs` / `src/main.rs`.
- Wire Tauri commands:
  - `get_engine_status() -> EngineStatus`
  - `send_engine_event(event: EngineEvent) -> EngineState`
  - `reset_engine() -> EngineState`
- Connect Tauri application state to an instance of `BornoEngine` wrapped in `Mutex`.

### Task 3: Sandbox User Interface
- Create modern, responsive sandbox UI:
  - Header with Engine Status badge (Version, Ready indicator).
  - Interactive test input box capturing keydown events and dispatching to Tauri commands.
  - Live preedit and candidate preview tags rendered directly from Rust engine output.
  - Event and state history inspection panel.
  - One-click "Run Deterministic Test" button that runs test sequences and validates results.

### Task 4: Automated Testing & CI
- Ensure `cargo test` executes cleanly and passes all unit tests.
- Add GitHub Actions CI workflow (`.github/workflows/ci.yml`) testing Rust and Node builds.

### Task 5: Manual Verification & Milestone Completion Report
- Launch the application locally using `npm run tauri dev`.
- Verify interactive typing, preedit updates, candidate generation, and the deterministic test button.
- Record the M0 Completion Report in `milestones/M0-completion-report.md`.
