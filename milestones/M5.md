## 1. Milestone Purpose, Scope & Architectural Boundaries

### 1.1 Purpose
Introduce a durable, versioned **Configuration and Settings System** into the Bangla Input Platform, cleanly separated into:
1. A pure, platform-independent configuration schema with semantic validation in the shared Rust core (`crates/borno-core/src/config.rs`).
2. A failure-safe, platform-appropriate local persistence and recovery manager in the Tauri desktop application layer (`src-tauri/src/config_store.rs`).
3. Infallible runtime application of validated preferences to the active `BornoEngine` without disrupting composition invariants or active text.
4. A functional, fully accessible **Settings Drawer** in the Desktop Sandbox (`Borno-Sandbox.exe`) with programmatic focus management, dirty-form state tracking, honest error reporting, and explicit confirmation for destructive actions.

## 3. Goals and Non-Goals

### 3.1 Specific In-Scope Outcomes for M5
1. **Typed, Versioned Configuration Schema:** Define `BornoConfig` (v1.0.0) in `crates/borno-core/src/config.rs` with serde serialization, field defaults (`#[serde(default)]`), and semantic validation.
2. **Failure-Safe Local Persistence:** Persist configuration in standard OS app-data directories using a platform-appropriate safe-replacement strategy that never deletes the destination before replacement succeeds.
3. **Resilient Recovery vs. Version Protection:**
   - Missing file -> generate defaults.
   - Corrupted/malformed JSON -> backup to timestamped `.corrupt.<timestamp>` file and regenerate defaults.
   - Syntactically valid but semantically invalid config -> backup to `.invalid.<timestamp>` and regenerate defaults.
   - Unsupported schema version -> **preserve untouched**, use in-memory defaults for session, and lock saving to prevent data destruction.
4. **Controlled Reset Flow for Unsupported Schemas:** Explicit user confirmation modal before destructive reset, creating a `.bak_unsupported.<timestamp>` backup, and unlocking persistence only upon verified success.
5. **Semantic Validation with Explicit Errors:** User-submitted changes via IPC are strictly validated; invalid values return descriptive errors without silent clamping.
6. **Infallible Live Engine Reconfiguration:** Reconfigure running engine parameters (`candidate_display_limit`, `auto_commit_on_mode_switch`, and preferred layout preference) as infallible field assignments after validation.
7. **Startup Mode & Preferred Layout Preferences:** Store `default_startup_mode` (applied only on cold initialization) and `preferred_fixed_layout` (applied when entering Fixed mode).
8. **Reset-to-Default:** Revert configuration on disk and in memory to factory defaults with an explicit confirmation step.
9. **Accessible Settings Drawer UI:** Glassmorphic settings panel with programmatic focus management, focus trapping, focus restoration on close, Escape/backdrop dismissal with unsaved change protection, real config path display, and form dirty-state tracking.
10. **Zero Regressions:** Maintain 100% pass rate across all 176 measured baseline tests.

## 5. Configuration Schema, Versioning & Validation

### 5.1 `BornoConfig` Schema Definition (`crates/borno-core/src/config.rs`)

```rust
use serde::{Deserialize, Serialize};
use crate::layout::FixedLayoutId;

/// Authoritative configuration schema for Borno (Schema Version 1.0.0).
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct BornoConfig {
    /// Schema format version (strictly "1.0.0" for M5)
    pub schema_version: String,

    /// Mode to initialize when the engine starts up
    #[serde(default = "default_startup_mode")]
    pub default_startup_mode: StartupMode,

    /// Preferred fixed keyboard layout when switching to Fixed mode
    #[serde(default = "default_preferred_fixed_layout")]
    pub preferred_fixed_layout: FixedLayoutId,

    /// Maximum number of candidates presented in candidate window (1..9, default 5)
    #[serde(default = "default_candidate_display_limit")]
    pub candidate_display_limit: usize,

    /// Auto-commit active preedit composition when switching input modes
    #[serde(default = "default_auto_commit_on_mode_switch")]
    pub auto_commit_on_mode_switch: bool,
}

fn default_startup_mode() -> StartupMode { StartupMode::Phonetic }
fn default_preferred_fixed_layout() -> FixedLayoutId { FixedLayoutId::National }
fn default_candidate_display_limit() -> usize { 5 }
fn default_auto_commit_on_mode_switch() -> bool { true }

/// Permitted startup modes for BornoEngine.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
pub enum StartupMode {
    Phonetic,
    Fixed,
    EnglishPassthrough,
}

impl Default for BornoConfig {
    fn default() -> Self {
        Self {
            schema_version: "1.0.0".to_string(),
            default_startup_mode: default_startup_mode(),
            preferred_fixed_layout: default_preferred_fixed_layout(),
            candidate_display_limit: default_candidate_display_limit(),
            auto_commit_on_mode_switch: default_auto_commit_on_mode_switch(),
        }
    }
}
```

### 5.2 Error Types Using Standard Library
Without introducing external dependencies like `thiserror`, the validation error type is defined cleanly:

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ConfigValidationError {
    UnsupportedSchemaVersion(String),
    InvalidCandidateDisplayLimit(usize),
}

impl std::fmt::Display for ConfigValidationError {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        match self {
            Self::UnsupportedSchemaVersion(ver) => {
                write!(f, "Unsupported schema version '{ver}'; this application supports '1.0.0'")
            }
            Self::InvalidCandidateDisplayLimit(val) => {
                write!(f, "Candidate display limit must be between 1 and 9 (received {val})")
            }
        }
    }
}

impl std::error::Error for ConfigValidationError {}

impl BornoConfig {
    /// Strictly validates semantic invariants of the configuration.
    pub fn validate(&self) -> Result<(), ConfigValidationError> {
        if self.schema_version != "1.0.0" {
            return Err(ConfigValidationError::UnsupportedSchemaVersion(self.schema_version.clone()));
        }
        if self.candidate_display_limit < 1 || self.candidate_display_limit > 9 {
            return Err(ConfigValidationError::InvalidCandidateDisplayLimit(self.candidate_display_limit));
        }
        Ok(())
    }
}
```

### 5.3 Order of Deserialization, Version Inspection & Validation
To ensure that unknown fields do not accidentally make an unsupported schema appear compatible:
1. **JSON Syntax Parse:** Parse string into generic `serde_json::Value`. If malformed JSON, trigger corruption recovery.
2. **Schema Version Inspection:** Inspect the `schema_version` property:
   - If missing or not a string: treat as unversioned/invalid file -> trigger recovery (`.invalid.<timestamp>` backup + default file).
   - If present and `schema_version != "1.0.0"` (whether older e.g. `"0.9.0"` or newer e.g. `"2.0.0"`):
     - **Do NOT proceed to typed deserialization.**
     - Treat as `UnsupportedSchemaVersion(version)`.
     - **Preserve file byte-for-byte untouched on disk.**
     - Load in-memory defaults, lock persistence (`read_only`), UI displays alert.
   - If present and `schema_version == "1.0.0"`: proceed to Step 3.
3. **Typed Deserialization:** Convert `Value` into `BornoConfig`. Missing individual fields safely receive their serde defaults (`default_candidate_display_limit`, etc.). If deserialization fails (type mismatch), trigger recovery (`.invalid.<timestamp>` backup + default file).
4. **Semantic Validation:** Execute `config.validate()`. If candidate limit is outside `1..=9`, trigger recovery (`.invalid.<timestamp>` backup + default file).

## 6. Failure-Safe Disk Persistence Specification

### 6.1 OS Storage Locations
Configuration files reside in the operating system's standard application data directory resolved dynamically via Tauri:
- **Windows:** `%APPDATA%\com.borno.sandbox\config.json` (resolved via `app.path().app_config_dir()`)
- **Linux:** `$XDG_CONFIG_HOME/com.borno.sandbox/config.json` or `~/.config/com.borno.sandbox/config.json`
- **macOS:** `~/Library/Application Support/com.borno.sandbox/config.json`

The backend dynamically exposes the exact resolved path via `get_config_path` IPC; the frontend never hardcodes paths.

### 6.2 Platform-Appropriate Safe Replacement Strategy
To avoid corrupted configuration files on crash, write interruption, or process abort:

```
1. Serialize BornoConfig to formatted JSON string.
2. Validate configuration in memory via config.validate().
3. Ensure parent directory exists (std::fs::create_dir_all).
4. Create temporary file on the EXACT SAME volume and directory:
   Path: <config_dir>/config.json.tmp.<process_id>_<timestamp>_<counter>
5. Open temporary file with write access, write JSON string.
6. Flush and sync physical data to storage:
   file.flush()?;
   file.sync_all()?;
   drop(file); // Ensure file handle is closed before moving
7. Replace destination file:
   std::fs::rename(&tmp_path, &dest_path)?;
8. If rename fails:
   std::fs::remove_file(&tmp_path);
   return Err(io_error);
```

#### Windows Filesystem Realities & Tested Guarantees:
- **Same Volume Guarantee:** Creating the temporary file in the destination directory ensures both `tmp_path` and `dest_path` reside on the same NTFS volume.
- **Replacement Semantics:** On Windows, Rust's `std::fs::rename` uses `MoveFileExW` with `MOVEFILE_REPLACE_EXISTING`.
- **Handling File Locks:** If another process (e.g. antivirus scanner or indexer) temporarily holds an exclusive lock on `config.json`, `std::fs::rename` will fail.
  - *Recovery:* The temporary file is cleaned up via `std::fs::remove_file(&tmp_path)`.
  - The destination `config.json` is **never deleted prior to replacement**; the previous valid configuration remains intact and unmodified.
  - An explicit error is returned to the user; the application never claims a save succeeded when replacement failed.
- **Temporary File Cleanup:** The application cleans up its own temporary file immediately if any write, sync, or rename step fails. Broad time-based sweeps of other processes' temporary files are omitted in M5 to avoid deleting active files belonging to concurrent processes.
- **Realistic Durability Statement:** The combination of `sync_all()` and same-volume rename protects against application crashes, thread termination, and partial writes. However, absolute immunity against hardware-level power loss depends on drive firmware write caching and cannot be claimed universally.

### 6.3 Resilient Recovery Policies

| Condition | Persistence Action | In-Memory Engine State | UI Notification |
|---|---|---|---|
| **Missing File** | Writes clean `BornoConfig::default()` to disk. | Defaults applied. | Informational badge: "Default configuration initialized." |
| **Missing File (Write Fails)** | Aborts write; leaves filesystem alone. | In-memory defaults applied. | Warning: "Running with in-memory defaults; persistence unavailable." |
| **Malformed JSON** | Renames to `config.json.corrupt.<timestamp>`, writes fresh defaults. | Defaults applied. | Warning: "Configuration corrupted; backed up to .corrupt and reset to defaults." |
| **Semantically Invalid (e.g. limit: 99)** | Renames to `config.json.invalid.<timestamp>`, writes fresh defaults. | Defaults applied. | Warning: "Configuration invalid; backed up to .invalid and reset to defaults." |
| **Unsupported Version (e.g. "2.0.0" or "0.9.0")** | **PRESERVES FILE UNTOUCHED.** Locks persistence (`read_only`). | Safe defaults for current session. | Alert: "Unsupported configuration version '{ver}' detected. File preserved; saving disabled." |
| **Read Permission Failure** | Leaves file untouched. Locks persistence. | Defaults applied. | Error: "Cannot read configuration (Permission Denied). Running in read-only mode." |
| **Write / Backup Failure** | Aborts destructive recovery; preserves existing file. | Retains in-memory defaults. | Error: "Failed to backup configuration: {io_error}. Existing file preserved." |

*Rule on Destructive Recovery:* Recovery that overwrites `config.json` is strictly restricted to corrupt or semantically invalid files and is preceded by creating a backup file. If creating the backup file fails, destructive recovery halts immediately.

### 6.4 Reset Behavior for Unsupported Schemas
When an unsupported schema is detected on disk, ordinary saves are locked. If the user initiates a Reset:
1. The UI displays an explicit high-severity confirmation modal:
   `"Warning: The configuration file on disk has an unsupported version (v{file_version}). Resetting will overwrite this file with v1.0.0 defaults. Are you sure you want to proceed?"`
2. **If Cancelled:** Operation aborts immediately. The file remains untouched and persistence remains locked.
3. **If Confirmed:**
   - A backup is created: `config.json.bak_unsupported_<timestamp>`.
   - If backup fails: abort destructive reset immediately; return explicit error; lock remains active; original file preserved.
   - If backup succeeds: execute atomic safe replacement of `config.json` with `BornoConfig::default()`.
   - If replacement fails: original file is preserved; return error; lock remains active.
   - If replacement succeeds: unlock persistence (`read_only = false`), synchronize live engine to defaults, and display green success banner: `"Configuration reset to defaults. Previous configuration backed up to {backup_path}."`

Does **not** change active layout or commit/discard active text mid-session. | Save preference; verify active composition and layout are unchanged; switch modes and verify new layout activates. |
| **Candidate Display Limit** | `candidate_display_limit` | `usize`<br>Range: `1..=9` | `5` | `limit >= 1 && limit <= 9`. ### 7.2 Detailed Analysis of Key Behaviors & Invariants

1. **Startup Mode vs. Active Mode:**
   - *Startup Mode:* A persistent preference governing what mode the engine initializes into upon application startup.
   - *Active Mode:* Ephemeral session state changed dynamically by the user via UI mode buttons or shortcuts.
   - *Invariant:* Saving settings modifies the saved startup preference for future launches; it must **never** unexpectedly switch the user's active typing mode during an ongoing session.

2. **Preferred Fixed Layout as Stored Preference (No Silent Mutation):**
   - Changing `preferred_fixed_layout` in Settings simply updates `engine.preferred_fixed_layout`.
   - It takes effect:
     1. At next cold initialization (if `default_startup_mode` is Fixed).
     2. The next time the engine enters Fixed mode (e.g. switching from Phonetic or English).
   - If the user is currently typing in Fixed mode:
     - Saving the preference does **NOT** abruptly swap the active layout.
     - Saving the preference does **NOT** touch the preedit buffer or commit/discard text.
     - If the user wants to switch the active layout immediately, they use the Header buttons (National, Probhat, Bijoy) or virtual keyboard selector, which is an explicit layout switch event.

3. **Candidate Display Limit Presentation Slicing:**
   - Linguistic candidate generation in `crates/borno-core/src/phonetic/candidates.rs` remains invariant.
   - `BornoEngine` holds `candidate_display_limit: usize` (1..=9).
   - In `update_composition()`, `BornoEngine` slices the presentation candidate list:
     ```rust
     if candidates.len() > self.candidate_display_limit {
         candidates.truncate(self.candidate_display_limit);
     }
     self.state.candidates = candidates;
     ```
   - *Verified Invariants:*
     - Candidate count never exceeds `candidate_display_limit`.
     - Candidate order and ranking are strictly preserved.
     - Fewer available candidates remain fewer (e.g. input `"b"` produces 1 candidate; limit 5 does not pad or synthesize candidates).
     - Verified fixture `"ka"` produces 3 candidates: `["কা", "ক্যা", "খা"]`. With limit 2, presentation contains exactly `["কা", "ক্যা"]`.

## 8. Transactional Settings Application & Lifecycle

### 8.1 Settings Application Sequence

```
User edits settings in React Drawer and clicks "Save Settings"
                                │
                                ▼
1. UI sends IPC: invoke('save_config', { config })
                                │
                                ▼
2. Tauri Backend acquires AppState.config_mutex:
   ├── Validates config in memory: config.validate()
   │   └── If Invalid: release lock, return Err(validation_error)
   │
   ├── Executes Safe Replacement to disk:
   │   ├── Write to config.json.tmp.<pid>_<ts>_<counter>
   │   ├── Flush, sync_all, drop file handle
   │   ├── std::fs::rename(tmp, dest)
   │   └── If Disk Write Fails:
   │       ├── remove_file(tmp)
   │       └── release lock, return Err(persistence_error)
   │
   └── Reconfigures Running Engine (Infallible Field Mutation):
       ├── Acquire state.engine.lock()
       ├── If Engine Mutex Poisoned:
       │   └── release lock, return Err(SavedButRestartRequired)
       ├── engine.set_candidate_display_limit(config.candidate_display_limit)
       ├── engine.set_auto_commit_on_mode_switch(config.auto_commit_on_mode_switch)
       ├── engine.set_preferred_fixed_layout(config.preferred_fixed_layout)
       └── Return Ok(effective_config)
                                │
                                ▼
3. UI synchronizes its state with effective_config:
   └── Displays transient green "Settings Saved Successfully" confirmation.
```

### 8.2 Failure Semantics & Honest Reporting
- **Validation Failure (`SaveFailed`):** Aborts before touching disk or engine. Engine and disk remain in sync. UI shows error banner.
- **Persistence Failure (`SaveFailed`):** Aborts before touching engine. Engine remains on valid existing settings. UI shows error banner.
- **Infallible Runtime Mutation:** Because runtime application involves only scalar and enum field updates (`candidate_display_limit`, `auto_commit_on_mode_switch`, `preferred_fixed_layout`) without memory allocation or layout recompilation, runtime application is infallible once validation succeeds.
- **Engine Mutex Poisoned (`SavedButRestartRequired`):** If a prior panic in another thread poisoned the engine mutex, disk persistence has succeeded, but runtime application cannot proceed. The backend reports: `"Settings saved to disk, but active engine is unresponsive. Restart required."` The UI reflects this amber state honestly.
- **Concurrency & Lock Order:**
  - Tauri `AppState` maintains `config_mutex: Mutex<()>` for config transactions and `engine: Mutex<BornoEngine>`.
  - Lock acquisition order: `config_mutex` -> `engine.lock()`.
  - Serializes configuration requests per process, preventing race conditions or interleaved temporary file writes.
  - Desktop sandbox operates as a single application process.
